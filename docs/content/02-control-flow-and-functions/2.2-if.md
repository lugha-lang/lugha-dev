## Step 1: if expressions
Kind: read

Like a block, an `if` has a value, the value of whichever branch ran.
Here lines 3 to 9 put one of three strings into `advice`, and `else if` on line 5 adds a second condition to check.
Press Run.

It prints `stay inside`, because `temperature > 30` is true and the other branches are skipped.
Change `31` on line 2 to `25` or `10` and run again to see the other two.

```lugha
fun main() {
    let temperature = 31;
    let advice = if temperature > 30 {
        "stay inside"
    } else if temperature > 20 {
        "go for a walk"
    } else {
        "take a jacket"
    };
    println(advice);
}
```

Output:

```text
stay inside
```

## Step 3: Boolean conditions
Kind: fix (start gives E0403 "expected bool, found i64")

`unread` is `3`, and line 3 uses it as the condition.
Will a number that isn't `0` count as true?

`lughac` says no, with E0403 again, the code for a value of the wrong type, this time "expected bool, found i64".
A condition must be a `bool`, and a number is never read as one, so the comparison has to be written out:

## Step 4: Braces and parentheses
Kind: fix (start gives E0201 "expected `{`, found identifier `println`")

Line 3 puts the condition in parentheses and leaves out the braces.
Which of the two is the problem?

The braces: it gives E0201, "expected `{`, found identifier `println`".
Parentheses around a condition are optional, so `if (unread > 0)` means the same as `if unread > 0`.
The code after the condition is always a block in braces, even when it holds one line, and so is the code after `else`, unless it's another `if`:

```lugha {3,4,5}
fun main() {
    let unread = 3;
    if (unread > 0) {
        println("you have mail");
    }
}
```

Put line 3's `println` in braces.

Start:

```lugha
fun main() {
    let unread = 3;
    if (unread > 0) println("you have mail");
}
```

Solution:

```lugha
fun main() {
    let unread = 3;
    if (unread > 0) {
        println("you have mail");
    }
}
```

Output (solution):

```text
you have mail
```
