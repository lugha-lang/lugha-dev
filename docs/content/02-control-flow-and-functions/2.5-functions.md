# 2.5 Functions

## Objectives

After this lesson the learner can:

- Declare a function with typed parameters and a return type, and know the order of functions in a file doesn't matter. [L1379, L1132]
- Know inference is local: parameters and return types are always written, never worked out from the body. [L672–676, L1383]
- Return the body's last expression, and know a trailing `;` throws it away (E0503). [L1379, L1049]
- Write `=` bodies. [L1383]
- Know parameters can't be reassigned, and shadow one with `let mut n = n;`. [L1400]
- Surprise: no overloading and no default parameters: a name means one function (E0302). [L1403]

(Moved to 2.3 if after planning: returning early with `return`, and recursion. Both need `if` to be shown.)

## Step 1: Function declaration
Kind: read

So far `main` has been the only function, and a new one is declared the same way.
After `fun` and the name come its parameters with their types, and after the `)` a `:` and the type it gives back.
`main` calls `area` on line 6.
Press Run.

It prints `21`.
`area` comes first here, but the order of functions in a file doesn't matter, so `main` could be at the top instead.
The types are what matter: `lughac` works out a `let`'s type from its value, but never a parameter's type, and never a return type from the body.
Leave the return type off, as `main` does on line 5, and the function gives back `()`.

```lugha
fun area(width: i64, height: i64): i64 {
    width * height
}

fun main() {
    println(area(7, 3));
}
```

Output:

```text
21
```

## Step 2: Return values
Kind: fix (start gives E0503 "`area` may end without returning a value of type i64")

`area`'s body is a block, so what it gives back is its last expression, as in Blocks and scopes.
Line 2 now ends with a `;`.
In Blocks and scopes that `;` gave a block `()` with only a warning, so what happens here?

This time it's an error, E0503, because line 1 promises an `i64` and the body no longer gives one.
The error points at the semicolon, and its help says to remove it, which gives this:

```lugha {2}
fun area(width: i64, height: i64): i64 {
    width * height
}

fun main() {
    println(area(7, 3));
}
```

Remove the `;` on line 2 and run again, or press Solve.

Start:

```lugha
fun area(width: i64, height: i64): i64 {
    width * height;
}

fun main() {
    println(area(7, 3));
}
```

Solution:

```lugha
fun area(width: i64, height: i64): i64 {
    width * height
}

fun main() {
    println(area(7, 3));
}
```

Output (solution):

```text
21
```

## Step 3: Expression bodies
Kind: read

A body that is a single expression can drop its braces too, with `=` standing in for them, as on line 1.
Run it, and it prints `21` again, because `= width * height;` means exactly the braces with `width * height` inside.

Its final `;` ends the declaration, so it doesn't throw the value away the way the `;` in step 2 did.
The return type is still written in this form, so you can see what `area` gives back without reading its body.

```lugha
fun area(width: i64, height: i64): i64 = width * height;

fun main() {
    println(area(7, 3));
}
```

Output:

```text
21
```

## Step 4: Immutable parameters
Kind: fix (start gives E0501 "cannot assign to `price`: it is not mutable", help "parameters are immutable; shadow it: `let mut price = price;`")

`with_tax` adds a tenth to `price` on line 2.
Can a function change its own parameter?

It can't: the output shows E0501 for line 2, because a parameter is like a `let` without `mut`.
The help in the output gives the fix, which is shadowing, from Variables.
`let mut price = price;` makes a copy you can change, and from the next line on, `price` means the copy:

```lugha {2}
fun with_tax(price: i64): i64 {
    let mut price = price;
    price = price + price / 10;
    price
}

fun main() {
    println(with_tax(200));
}
```

Add it as a new line 2.

Start:

```lugha
fun with_tax(price: i64): i64 {
    price = price + price / 10;
    price
}

fun main() {
    println(with_tax(200));
}
```

Solution:

```lugha
fun with_tax(price: i64): i64 {
    let mut price = price;
    price = price + price / 10;
    price
}

fun main() {
    println(with_tax(200));
}
```

Output (solution):

```text
220
```

## Step 5: No overloading
Kind: fix (start gives E0302 "`area` is defined more than once", and E0405 for the call on line 7)

Lines 1 and 3 both declare a function called `area`, one with two parameters and one with one.
Will line 7 call the one that takes a single number?

No: the output shows E0302, "`area` is defined more than once".
It also shows E0405 for line 7, which says the call gives one argument to an `area` that takes two.
Two functions can't share a name, whatever their parameters, and a parameter can't have a default value either, so each way of calling needs its own function.
Give the second one a name of its own:

```lugha {3,7}
fun area(width: i64, height: i64): i64 = width * height;

fun square_area(side: i64): i64 = side * side;

fun main() {
    println(area(7, 3));
    println(square_area(4));
}
```

Rename it on lines 3 and 7, or press Solve.

Start:

```lugha
fun area(width: i64, height: i64): i64 = width * height;

fun area(side: i64): i64 = side * side;

fun main() {
    println(area(7, 3));
    println(area(4));
}
```

Solution:

```lugha
fun area(width: i64, height: i64): i64 = width * height;

fun square_area(side: i64): i64 = side * side;

fun main() {
    println(area(7, 3));
    println(square_area(4));
}
```

Output (solution):

```text
21
16
```

- Every program was run in the sandbox (pinned lughac m159). Also tested: `fun area(width, height): i64` is E0201 "expected `:`, found `,`".
- For `../lugha`, found while testing:
  - `fun area(width: i64, height: i64) { width * height }` (no return type, a tail of type `i64`) compiles with no error or warning, and calling it prints `()`.
