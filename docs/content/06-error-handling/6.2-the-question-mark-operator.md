## Step 1: ? on Result
Kind: read

`?` after a `Result` gives the value inside an `Ok`, or returns the `Err` from the function at once.
Line 2 reads a file with `read_file(path)?`, so `text` is the file's text, a plain `string`.
Line 3 prints the name of the file it read.
Line 8 writes `notes.txt` first, and prints the `Ok` that `write_file` gives.
Will line 3 print for `other.txt`, which isn't there?
Press Run.

It doesn't: the failed read returns its `Err` at line 2, and nothing after the `?` runs.

```lugha
fun note_length(path: string): Result<i64, string> {
    let text = read_file(path)?;
    println("read {path}");
    Ok(text.len)
}

fun main() {
    println(write_file("notes.txt", "milk\neggs\n"));
    println(note_length("notes.txt"));
    println(note_length("other.txt"));
}
```

Output:

```text
Ok(10)
read notes.txt
Ok(10)
Err("No such file or directory")
```

## Step 2: ? on Option
Kind: read

In a function that returns an `Option`, `?` works on an `Option` the same way: it gives the value inside a `Some`, or returns `None`.
`sum_two` parses two strings on lines 2 and 3, and either `?` returns `None` when its string isn't a number.
Line 4 adds the numbers only when both parsed.
Press Run.

```lugha
fun sum_two(a: string, b: string): Option<i64> {
    let x = parse_i64(a)?;
    let y = parse_i64(b)?;
    Some(x + y)
}

fun main() {
    println(sum_two("2", "3"));
    println(sum_two("2", "three"));
}
```

Output:

```text
Some(5)
None
```

## Step 3: Error types
Kind: fix (start gives E0424 "`?` can't return here", help "a missing value isn't an error by itself: handle the `Option` with `match`")

`?` returns a failure as the function's own, so it has to fit the function's return type.
On a `Result`, the error types must be the same, and `map_err` can change one first.
`total` on line 1 returns a `Result<i64, string>`, and line 3 uses `?` on the `Option` that `parse_i64` gives.
A `None` has no error in it to return, and `lughac` stops at line 3 with E0424, "`?` can't return here".
Its help suggests a `match`, but `ok_or("not a number")` is shorter.
It turns the `Option` into a `Result`, with that string as its error, and then `?` works:

```lugha {3}
fun total(path: string): Result<i64, string> {
    let text = read_file(path)?;
    let n = parse_i64(text.trim()).ok_or("not a number")?;
    Ok(n * 2)
}

fun main() {
    println(write_file("n.txt", "21\n"));
    println(total("n.txt"));
}
```

Add `.ok_or("not a number")` before the `?` on line 3, or press Solve.

Start:

```lugha
fun total(path: string): Result<i64, string> {
    let text = read_file(path)?;
    let n = parse_i64(text.trim())?;
    Ok(n * 2)
}

fun main() {
    println(write_file("n.txt", "21\n"));
    println(total("n.txt"));
}
```

Solution:

```lugha
fun total(path: string): Result<i64, string> {
    let text = read_file(path)?;
    let n = parse_i64(text.trim()).ok_or("not a number")?;
    Ok(n * 2)
}

fun main() {
    println(write_file("n.txt", "21\n"));
    println(total("n.txt"));
}
```

Output (solution):

```text
Ok(3)
Ok(42)
```

## Step 4: Errors in main
Kind: fix (start gives E0424 "`?` can't return here", help "`main` can't return an error: handle it with `match`")

`main` returns nothing, so `?` has no `Err` to return from it.
Line 2 uses `?` there anyway, and `lughac` stops at line 2 with E0424, whose help says to handle the error with `match`.
So `main` matches on the `Result` itself and decides what to print:

```lugha {2,3,4,5}
fun main() {
    match read_file("notes.txt") {
        Ok(text) => println(text),
        Err(e) => println("can't read notes.txt: {e}"),
    }
}
```

Replace lines 2 and 3 with the `match`, or press Solve.

Start:

```lugha
fun main() {
    let text = read_file("notes.txt")?;
    println(text);
}
```

Solution:

```lugha
fun main() {
    match read_file("notes.txt") {
        Ok(text) => println(text),
        Err(e) => println("can't read notes.txt: {e}"),
    }
}
```

Output (solution):

```text
can't read notes.txt: No such file or directory
```
