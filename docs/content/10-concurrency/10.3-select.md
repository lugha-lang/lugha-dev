# 10.3 select

## Objectives

After this lesson the learner can (one step each, titles from the outline):

4. **Deadlock**: every green thread waiting is a panic, exit 101. [L1189]

## Step 1: select
Kind: read

In 10.2 `main` read from one channel, but with two, a `recv` on one would wait there while the other already has a value.
`select` on line 13 waits on both and takes whichever is ready first.
Each arm names a channel operation, then `=>` and what to do, as a `match` arm does.
On line 14, `f` is the `Option` that `fruit.recv()` gave, in scope only in that arm.
Press Run.

When both channels have a value ready, `select` picks one of them.
The pick looks random but comes out the same on every run, and it gives each arm its turn, so one busy channel can't shut out the other.


```lugha
fun send_all(c: Chan<string>, words: string[]) {
    for w of words {
        c.send(w);
    }
}

fun main() {
    let fruit: Chan<string> = Chan.new();
    let tools: Chan<string> = Chan.new();
    spawn send_all(fruit, ["apple", "pear"]);
    spawn send_all(tools, ["saw", "drill"]);
    for i of range(0, 4) {
        select {
            f = fruit.recv() => println("fruit: {f.unwrap()}"),
            t = tools.recv() => println("tool: {t.unwrap()}"),
        }
    }
}
```

Output:

```text
fruit: apple
tool: saw
fruit: pear
tool: drill
```

## Step 2: Timeouts with after
Kind: read

The `select` in step 1 waits as long as it takes, and an `after` arm puts a limit on that.
Here `slow` sleeps for half a second before it sends.
`after(200)` on line 18 runs if no other arm could go on within 200 milliseconds.
Each pass of the loop is a new `select`, so the 200 milliseconds start again, and the loop either gets the message or prints "still waiting".
Press Run.

Two waits of 200 milliseconds end before the message arrives, so "still waiting" prints twice.


```lugha
import std.task;

fun slow(c: Chan<string>) {
    task.sleep(500);
    c.send("done");
}

fun main() {
    let c: Chan<string> = Chan.new();
    spawn slow(c);
    let mut waiting = true;
    while waiting {
        select {
            m = c.recv() => {
                println(m.unwrap());
                waiting = false;
            },
            after(200) => println("still waiting"),
        }
    }
}
```

Output:

```text
still waiting
still waiting
done
```

## Step 3: select with default
Kind: read

An `after` arm still waits up to its limit.
A `default` arm runs when no other arm can go on at once, so a `select` with one never waits.
Arms can send too: `c.send(i)` on line 5 goes on when this channel has room.
Press Run.

The channel holds one value, so the first send is queued and the next two fall to `default` on line 6.
A `select` can't have both `after` and `default`, because with `default` it never waits long enough for `after` to fire, so `lughac` gives E0438.


```lugha
fun main() {
    let c: Chan<i64> = Chan.buffered(1);
    for i of range(1, 4) {
        select {
            c.send(i) => println("queued {i}"),
            default => println("full, dropped {i}"),
        }
    }
    println(c.recv());
}
```

Output:

```text
queued 1
full, dropped 2
full, dropped 3
Some(1)
```

## Step 4: Deadlock
Kind: fix (start prints "got 1", "got 2", "got 3", then panics: deadlock)

Without `after` or `default`, a `select` can wait forever, and so can a plain `recv`.
This `produce` from 10.2 has lost its `close`.
Press Run.

`main` takes the three values, then waits in `recv` on line 10 for a fourth, but `produce` has finished without closing the channel.
When no green thread can go on and none is sleeping, the program panics with "deadlock: every green thread is waiting" and exits with code 101.
Closing the channel once `produce` has sent everything gives `recv` its `None`, so the loop ends:


```lugha {5}
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
    }
    c.close();
}

fun main() {
    let c: Chan<i64> = Chan.new();
    spawn produce(c);
    while let Some(v) = c.recv() {
        println("got {v}");
    }
    println("done");
}
```

Add `c.close();` as line 5, or press Solve.

Start:

```lugha
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
    }
}

fun main() {
    let c: Chan<i64> = Chan.new();
    spawn produce(c);
    while let Some(v) = c.recv() {
        println("got {v}");
    }
    println("done");
}
```

Output (start):

```text
got 1
got 2
got 3
panic: deadlock: every green thread is waiting
```

Solution:

```lugha
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
    }
    c.close();
}

fun main() {
    let c: Chan<i64> = Chan.new();
    spawn produce(c);
    while let Some(v) = c.recv() {
        println("got {v}");
    }
    println("done");
}
```

Output (solution):

```text
got 1
got 2
got 3
done
```
