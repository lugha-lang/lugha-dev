## Step 1: Actor declaration
Kind: read

The green threads so far shared values through channels.
An actor is a green thread that keeps its own state, and other threads reach it only by calling its methods.
`actor Counter` on line 1 declares the state, the field `count` on line 2, and the methods, as a struct and its `impl` would together.
Inside the methods `self` is the state, so line 5, in `add`, changes `count`.
Line 12 starts the actor with `spawn` and the state's first value.
Press Run.

Only the actor's own methods reach its fields, so `c.count` in `main` would be E0439.
A field may not hold a `Ref` either, because that box would then be shared outside the actor, and that's E0439 too.


```lugha
actor Counter {
    count: i64,

    fun add(mut self, n: i64) {
        self.count += n;
    }

    fun get(self): i64 = self.count;
}

fun main() {
    let c = spawn Counter { count: 0 };
    c.add(2);
    c.add(3);
    println(c.get());
}
```

Output:

```text
5
```

## Step 2: Starting an actor
Kind: fix (start gives E0439 "an actor's state exists only inside the actor: start `Counter` with `spawn`" on line 14, and E0501 on line 16)

Step 1 started `Counter` from a literal, but an associated function can make the state too: `new` on line 4 returns `Self`, the actor's state.
Line 14 calls it without `spawn`.
Press Run.

That's E0439: the state exists only inside the actor, so it has to be started with `spawn`.
The E0501 on line 16 comes from the same mistake: without `spawn`, `d` is a plain value.
Calling `add` on it would need `let mut`, which a handle's `mut self` methods don't.
Copies of a handle, like `d` on line 15, reach the same actor, so `d.add(5)` shows up in `c.get()`.
The fixed `main.la`:


```lugha {14}
actor Counter {
    count: i64,

    fun new(start: i64): Self = Self { count: start };

    fun add(mut self, n: i64) {
        self.count += n;
    }

    fun get(self): i64 = self.count;
}

fun main() {
    let c = spawn Counter.new(10);
    let d = c;
    d.add(5);
    println(c.get());
}
```

## Step 3: Messages as method calls
Kind: read

Calling a method on a handle sends the actor a message, and the actor handles its messages one at a time, in the order they came.
`log` returns nothing, so `l.log("first")` on line 14 is queued and `main` goes on at once.
Press Run.

"main goes on" prints before "log: first", because `main` didn't wait for `log`.
`count` returns a value, so line 17 waits for it, and by then both messages to `log` have been handled.


```lugha
actor Logger {
    lines: i64,

    fun log(mut self, s: string) {
        println("log: {s}");
        self.lines += 1;
    }

    fun count(self): i64 = self.lines;
}

fun main() {
    let l = spawn Logger { lines: 0 };
    l.log("first");
    println("main goes on");
    l.log("second");
    println(l.count());
}
```

Output:

```text
main goes on
log: first
log: second
2
```

## Step 4: Stopping an actor
Kind: read

An actor runs until it's stopped or the program ends, and every handle has `stop()` and `join()` for that.
`stop` on line 12 is a message too, so the `show` queued before it still runs, then the actor ends.
`join` waits until the actor has ended and gives an `Option<string>`: `None` when it was stopped.
Press Run.

The actor behind `b` has `by: 0`, so `show` divides by zero on line 5, and its panic message prints.
The panic ends only that actor, and `b.join()` on line 17 gives `Some` with the message.
So a panic stays inside its actor: `main` learns of it from `join`, and anyone who calls that actor afterwards panics instead.


```lugha
actor Divider {
    by: i64,

    fun show(self, n: i64) {
        println(n / self.by);
    }
}

fun main() {
    let a = spawn Divider { by: 2 };
    a.show(10);
    a.stop();
    println(a.join());

    let b = spawn Divider { by: 0 };
    b.show(10);
    println(b.join());
    println("main still runs");
}
```

Output:

```text
5
None
Some("division by zero at src/main.la:5:19")
main still runs
```
