## Step 1: Channels
Kind: read

In 10.1 two threads shared a `Ref`, and a channel is another way for them to work together: one green thread hands values to another.
`Chan.new()` on line 9 makes one, and it carries `i64` values because line 9 writes `Chan<i64>`.
Passing `c` to `produce` copies the handle, and both copies name the same channel; `c.is(d)` tells whether two handles do.
`c.send(i)` on line 3 waits until a receiver takes the value, and `c.recv()` on line 12 waits for one to arrive.
Press Run.

`recv` gives an `Option`, so line 12 prints each value wrapped in `Some`.
Each "sent" line comes after `main` has taken that value, though not always after `main` has printed it, as "sent 1" shows.


```lugha
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
        println("sent {i}");
    }
}

fun main() {
    let c: Chan<i64> = Chan.new();
    let t = spawn produce(c);
    for i of range(0, 3) {
        println(c.recv());
    }
    t.join();
}
```

Output:

```text
sent 1
Some(1)
Some(2)
sent 2
sent 3
Some(3)
```

## Step 2: Buffered channels
Kind: read

This time `Chan.buffered(3)` on line 9 makes a channel that holds up to 3 values, so `send` waits only when it's full.
`join` on line 11 waits for `produce` to finish, and it can, because all three values fit before `main` takes any.
Press Run.

`try_recv` on lines 12 to 15 takes a value if one is ready, without waiting.
Line 15 finds the channel empty, so it gets `None` at once.


```lugha
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
        println("sent {i}");
    }
}

fun main() {
    let c: Chan<i64> = Chan.buffered(3);
    let t = spawn produce(c);
    t.join();
    println(c.try_recv());
    println(c.try_recv());
    println(c.try_recv());
    println(c.try_recv());
}
```

Output:

```text
sent 1
sent 2
sent 3
Some(1)
Some(2)
Some(3)
None
```

## Step 3: Closing a channel
Kind: read

So far `main` knew to stop after three values, and `c.close()` on line 5 lets the sender say when it's done instead.
After it, `recv` gives `None` once the values already sent have been taken, so `while let` on line 11 runs until then.
Press Run.

A closed channel's `recv` keeps giving `None`, as line 15 shows.
Sending on a closed channel panics with "send on a closed channel", and closing it again panics with "close of a closed channel".
So the thread that sends is the one to close the channel, once it has sent everything.


```lugha
fun produce(c: Chan<i64>) {
    for i of range(1, 4) {
        c.send(i);
    }
    c.close();
}

fun main() {
    let c: Chan<i64> = Chan.new();
    let t = spawn produce(c);
    while let Some(v) = c.recv() {
        println("got {v}");
    }
    println("closed");
    println(c.recv());
    t.join();
}
```

Output:

```text
got 1
got 2
got 3
closed
None
```
