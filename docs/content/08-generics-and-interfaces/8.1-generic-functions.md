## Step 1: Generic functions
Kind: read

Some functions do the same thing whatever type they're given.
Taking the first element works the same for an `i64[]` as for a `string[]`, so writing it twice would repeat the same body.
A generic function is written once, with a type parameter standing for the type: `T` in `first<T>` on line 1.
`T` is used wherever that type goes, so `first` takes a `T[]` and gives back an `Option<T>`.
Each call fills `T` in from its argument: line 11 uses `first` with `i64` and line 12 with `string`, and neither is written.
`empty` on line 8 takes no arguments, so line 13's `: string[]` fills `T` in, and without it the call is E0412.
Press Run.

```lugha
fun first<T>(xs: T[]): Option<T> {
    if xs.len == 0 {
        return None;
    }
    Some(xs[0])
}

fun empty<T>(): T[] = [];

fun main() {
    println(first([3, 4]));
    println(first(["tea", "milk"]));
    let names: string[] = empty();
    println(names);
}
```

Output:

```text
Some(3)
Some("tea")
[]
```

## Step 2: Type bounds
Kind: fix (start gives E0404 "cannot apply `==` to T", help "declare `T: Eq`")

`first` only passed its `T` along, which any type allows, but `count_of` compares two `T`s with `==` on line 4.
Press Run.

`lughac` stops at line 4 with E0404, "cannot apply `==` to T", and its help gives the fix: declare `T: Eq`.
A bound says what `T` must support, `Eq` for `==` and `Ord` for `<`, so this one needs `T: Eq`:

```lugha {1}
fun count_of<T: Eq>(xs: T[], wanted: T): i64 {
    let mut n = 0;
    for x of xs {
        if x == wanted {
            n += 1;
        }
    }
    n
}

fun main() {
    println(count_of([1, 2, 1], 1));
    println(count_of(["a", "b"], "c"));
}
```

Add `: Eq` after `T` on line 1, or press Solve.
`Ord` doesn't bring `==` with it, so a function that uses both declares `T: Ord + Eq`.

Start:


## Step 3: Numeric bounds
Kind: fix (start gives E0401 "float literal where T expected")

Arithmetic on a `T` needs a bound too: `T: Num` allows it, along with `==`, `<`, and an integer literal where a `T` goes.
So `total` starts its sum from `0` on line 2 and adds up `i64`s and `f64`s alike.
`half` on line 9 multiplies by `0.5`, a float literal, but a `Num` can be an integer type too.
Press Run.

`lughac` stops at line 9 with E0401, "float literal where T expected".
`T: Float` is met only by `f32` and `f64`, and allows everything `Num` does as well as float literals:

```lugha {9}
fun total<T: Num>(xs: T[]): T {
    let mut sum: T = 0;
    for x of xs {
        sum += x;
    }
    sum
}

fun half<T: Float>(x: T): T = x * 0.5;

fun main() {
    println(total([1, 2, 3]));
    println(total([0.5, 0.25]));
    println(half(3.0));
}
```

Change `Num` to `Float` on line 9, or press Solve.
