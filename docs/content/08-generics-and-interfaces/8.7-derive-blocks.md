# 8.7 Derive blocks

## Objectives

After this lesson the learner can (one step each, titles from the outline):

1. **Derive blocks**: `derive Describe for i64 { … }`; items only through a bound, `5.describe()` is E0415. [L371, L825]

## Step 1: Derive blocks
Kind: fix (start gives E0415 "no method `describe` on `i64`")

Up to now a type met an interface by having its methods in its own `impl`.
A derive block instead says, in one place, how a type meets it.
Line 5 says how every `i64` meets `Describe`, and line 9 does the same for `string`.
`tell` on line 13 takes any `T: Describe`, so it can be called with either.
Press Run.

`lughac` gives E0415 on line 19.
A block's items don't become methods of `i64`, so they are reached only through a bound such as `tell`'s.
Change line 19 to `tell(5);`; Solve does it for you.

Start:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "the number {self}";
}

derive Describe for string {
    fun describe(self): string = "the text \"{self}\"";
}

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell("hi");
    println(5.describe());
}
```

Solution:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "the number {self}";
}

derive Describe for string {
    fun describe(self): string = "the text \"{self}\"";
}

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell("hi");
    tell(5);
}
```

Output (solution):

```text
the text "hi"
the number 5
```

## Step 2: Deriving for structs
Kind: fix (start gives E0451 "`Book` doesn't meet `Describe`: `price` is `f64`, which no `derive Describe` block covers")

`derive Describe for struct` on line 15 covers every struct at once.
Inside it, `derive.fields(self, (), part)` calls `part` once per field, in order, and gives back an array of the results.
`part` is passed as a value, as in Functions as values.
`part` gets the second argument as `ctx`, then the field's name and value.
Here `ctx` is `()`, nothing; step 7 puts it to use.
`part` must be generic over one `F: Describe`, since each field has its own type.
Press Run.

`lughac` gives E0451: `price` is an `f64`, and no block covers `f64`.
A struct meets `Describe` only when each of its fields does.
Add a block for `f64` after line 11; Solve does it for you.

Start:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive Describe for string {
    fun describe(self): string = "\"{self}\"";
}

fun part<F: Describe>(ctx: (), name: string, field: F): string = "{name} is {field.describe()}";

derive Describe for struct {
    fun describe(self): string = derive.fields(self, (), part).join(", ");
}

struct Book { title: string, pages: i64, price: f64 }

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell(Book { title: "Dune", pages: 412, price: 9.5 });
}
```

Solution:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive Describe for string {
    fun describe(self): string = "\"{self}\"";
}

derive Describe for f64 {
    fun describe(self): string = "{self}";
}

fun part<F: Describe>(ctx: (), name: string, field: F): string = "{name} is {field.describe()}";

derive Describe for struct {

}

struct Book { title: string, pages: i64, price: f64 }

    println(x.describe());
}

fun main() {
    tell(Book { title: "Dune", pages: 412, price: 9.5 });
}
```

Output (solution):

```text
title is "Dune", pages is 412, price is 9.5
```

## Step 3: Deriving for enums
Kind: read

`derive Describe for enum` on line 15 covers every enum.
`derive.variant(self, (), part)` on line 17 gives a tuple: the variant's name, and an array of what `part` returns for each payload.
Each payload has no name of its own, so `part` gets the variant's name, unused here.
`Dot` has no payloads, so its array is empty.
`derive.index(self)` on line 18 is the variant's position in the enum, counting from 0.
Press Run.

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive Describe for string {
    fun describe(self): string = "\"{self}\"";
}

fun part<F: Describe>(ctx: (), name: string, field: F): string = field.describe();

derive Describe for enum {
    fun describe(self): string {
        let (name, parts) = derive.variant(self, (), part);
        return "variant {derive.index(self)}, {name}({parts.join(", ")})";
    }
}

enum Shape { Dot, Square(i64), Label(string, i64) }

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell(Shape.Dot);
    tell(Shape.Square(3));
    tell(Shape.Label("door", 2));
}
```

Output:

```text
variant 0, Dot()
variant 1, Square(3)
variant 2, Label("door", 2)
```

## Step 4: A type's own item
Kind: read

`Author` on line 21 is a struct, so the block on line 15 would cover it.
It has its own `describe` on line 24 instead, with exactly the interface's signature, and that one is used.
This is how `eq` and `hash` worked in Equality, ordering and printing.
With any other signature, such as `fun describe(self): i64`, `lughac` gives E0422 at line 33.
Press Run.

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive Describe for string {
    fun describe(self): string = "\"{self}\"";
}

fun part<F: Describe>(ctx: (), name: string, field: F): string = "{name} is {field.describe()}";

derive Describe for struct {
    fun describe(self): string = derive.fields(self, (), part).join(", ");
}

struct Book { title: string, pages: i64 }

struct Author { name: string, born: i64 }

impl Author {
    fun describe(self): string = "{self.name}, born {self.born}";
}

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell(Book { title: "Dune", pages: 412 });
    tell(Author { name: "Frank Herbert", born: 1920 });
}
```

Output:

```text
title is "Dune", pages is 412
Frank Herbert, born 1920
```

## Step 5: Overlapping blocks
Kind: fix (start gives E0452 "two `derive Describe` blocks cover `i64[]`")

A block can take type parameters, as line 9 does: it covers `T[]` for every `T` that meets `Describe`.
Line 13 adds a block for `i64[]`.
Line 23's array of arrays is covered by line 9 too, since `i64[]` meets `Describe` through it.
Press Run.

`lughac` gives E0452 on line 13: both blocks cover `i64[]`, and each type gets its items from one block.
Remove lines 13 to 15; Solve does it for you.

E0452 has a second cause: a block must be in the module that declares its interface.
A file is a module, as Modules will show, and `Display` is declared in the prelude.
So `derive Display for i64` in this file is E0452 as well.

Start:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive<T: Describe> Describe for T[] {
    fun describe(self): string = "a list of {self.len}";
}

derive Describe for i64[] {
    fun describe(self): string = "some numbers";
}

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell([1, 2, 3]);
    tell([[1], [2]]);
}
```

Solution:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive<T: Describe> Describe for T[] {
    fun describe(self): string = "a list of {self.len}";
}

fun tell<T: Describe>(x: T) {
    println(x.describe());
}

fun main() {
    tell([1, 2, 3]);
    tell([[1], [2]]);
}
```

Output (solution):

```text
a list of 3
a list of 2
```

## Step 6: derive.all and derive.fold
Kind: read

`Gauge` on line 1 has two items, and the struct block on line 15 writes both.
A block for one type can't use `Self`, so line 7 writes `i64` where the interface says `Self`.
Line 16, in the struct block, keeps `Self`.
`derive.all(self, other, near)` on line 16 calls `near` on each pair of matching fields and is `true` when every call is.
It stops at the first `false`.
`near` gets the field's name and the two values; there is no `ctx`.
`derive.fold(self, 0, add_up)` on line 17 starts from `0` and passes the running result through `add_up` once per field, as `sum`.
Press Run.

```lugha
interface Gauge {
    fun close_to(self, other: Self): bool;
    fun total(self): i64;
}

derive Gauge for i64 {
    fun close_to(self, other: i64): bool = self - other <= 1 && other - self <= 1;
    fun total(self): i64 = self;
}

fun near<F: Gauge>(name: string, x: F, y: F): bool = x.close_to(y);

fun add_up<F: Gauge>(sum: i64, name: string, part: F): i64 = sum + part.total();

derive Gauge for struct {
    fun close_to(self, other: Self): bool = derive.all(self, other, near);
    fun total(self): i64 = derive.fold(self, 0, add_up);
}

struct Reading { morning: i64, evening: i64 }

fun compare<T: Gauge>(a: T, b: T) {
    println("{a.total()} and {b.total()}, close: {a.close_to(b)}");
}

fun main() {
    let a = Reading { morning: 20, evening: 25 };
    compare(a, Reading { morning: 21, evening: 24 });
    compare(a, Reading { morning: 23, evening: 25 });
}
```

Output:

```text
45 and 45, close: true
45 and 48, close: false
```

## Step 7: derive.build
Kind: read

An interface item can take no `self`, as `parse` on line 2 does.
It is called on a type, as `T.parse(s)` on line 26.
`derive.build(s.split(","), field)` on line 21 builds a struct one field at a time.
For each field it calls the function `field` on line 13.
`field` gets the split parts as `ctx`, then the field's name, its position from 0, and the number of fields.
Line 17 parses one part with `F`'s own `parse`, so each field is read at its own type.
The first `Err` stops it and is the result; otherwise it is `Ok` with the struct.
Press Run.

```lugha
interface Parse {
    fun parse(s: string): Result<Self, string>;
}

derive Parse for i64 {
    fun parse(s: string): Result<i64, string> = parse_i64(s).ok_or("`{s}` isn't a number");
}

derive Parse for string {
    fun parse(s: string): Result<string, string> = Ok(s);
}

fun field<F: Parse>(parts: string[], name: string, at: i64, count: i64): Result<F, string> {
    if parts.len != count {
        return Err("expected {count} parts, got {parts.len}");
    }
    return F.parse(parts[at]);
}

derive Parse for struct {
    fun parse(s: string): Result<Self, string> = derive.build(s.split(","), field);
}

struct Book { title: string, pages: i64 }

fun read<T: Parse>(s: string): Result<T, string> = T.parse(s);

fun main() {
    for line of ["Dune,412", "Dune,many", "Dune"] {
        let book: Result<Book, string> = read(line);
        println(book);
    }
}
```

Output:

```text
Ok(Book { title: "Dune", pages: 412 })
Err("`many` isn't a number")
Err("expected 2 parts, got 1")
```
