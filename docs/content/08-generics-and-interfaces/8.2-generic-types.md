## Step 1: Generic structs
Kind: fix (start gives E0418 "`Pair` takes 1 type argument but 0 were given", twice on line 3)

A struct can take a type parameter as a function does: `Pair<T>` on line 1 holds two values of one type, `T`.
Line 6 builds a pair of numbers and line 7 a pair of strings, and `T` comes from the fields, as it came from a function's arguments.
In a type, though, a generic struct is written with its argument, as in `Pair<i64>`.
Line 3 writes a bare `Pair` twice.
Press Run.

Both of line 3's `Pair`s are E0418, "`Pair` takes 1 type argument but 0 were given".
`swap_pair` is called with both pairs, so it has to be generic itself:

```lugha {3}
struct Pair<T> { left: T, right: T }

fun swap_pair<T>(p: Pair<T>): Pair<T> = Pair { left: p.right, right: p.left };

fun main() {
    let numbers = Pair { left: 1, right: 2 };
    let words = Pair { left: "tea", right: "milk" };
    println(swap_pair(numbers));
    println(swap_pair(words));
}
```

Add `<T>` after `swap_pair` and write `Pair<T>` in both places; Solve does it for you.

Start:

```lugha

```

## Step 2: Generic enums
Kind: read

Enums take type parameters in the same place.
`List<T>` on lines 1 to 4 is the list from Recursive enums, which held only numbers, now holding any type.
Line 14 builds a list of strings, and `size` on line 6, generic itself, counts it.
`Option<T>`, which `first` gave back in Generic functions, is declared this way too.
Press Run.

```lugha
enum List<T> {
    Nil,
    Cons(T, List<T>),
}

fun size<T>(list: List<T>): i64 {
    match list {
        Nil => 0,
        Cons(_, rest) => 1 + size(rest),
    }
}

fun main() {
    let words = List.Cons("tea", List.Cons("milk", List.Nil));
    println(words);
    println(size(words));
}
```

Output:

```text
Cons("tea", Cons("milk", Nil))
2
```

## Step 3: Generic impl blocks
Kind: read

Methods for a generic type go in an `impl` block that names its parameter, as `impl Stack<T>` on line 3 does.
There `T` stands for the element type, and `Self` for `Stack<T>`.
Line 23's `Stack<i64>` fills in `T` for `Stack.new()`, as `: string[]` did for `empty`.
A second block can add a bound: `total`, in `impl Stack<T: Num>` on line 18, exists only for stacks of numbers.
Its `0` is a `T`, as `Num` allows.
Calling it on `words` would be E0419, "`string` doesn't satisfy `Num`".
Press Run.

```lugha
struct Stack<T> { items: T[] }

impl Stack<T> {
    fun new(): Self = Self { items: [] };

    fun push(mut self, item: T) {
        self.items.push(item);
    }

    fun top(self): Option<T> {
        if self.items.len == 0 {
            return None;
        }
        Some(self.items[self.items.len - 1])
    }
}

impl Stack<T: Num> {
    fun total(self): T = self.items.fold(0, fun(sum, x) = sum + x);
}

fun main() {
    let mut numbers: Stack<i64> = Stack.new();
    numbers.push(3);
    numbers.push(4);
    println(numbers.top());
    println(numbers.total());
    let mut words: Stack<string> = Stack.new();
    words.push("tea");
    println(words.top());
}
```

Output:

```text
Some(4)
7
Some("tea")
```
