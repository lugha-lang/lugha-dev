## Step 1: Interface values
Kind: fix (start gives E0403 "expected Circle, found Square", label "the first element is Circle")

With `T: Shape`, an array holds one type that meets `Shape`.
An interface is also a type, and a `Shape` value can hold a value of any type that meets it.
Line 17 puts a circle and a square in one array.
Press Run.

`lughac` stops at line 17 with E0403, "expected Circle, found Square": the array takes its type from its first element.
A value becomes a `Shape` only where a `Shape` is expected, so write the array's type:

```lugha {17}
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Square {
    fun area(self): f64 = self.side * self.side;
}

fun main() {
    let shapes: Shape[] = [Circle { r: 1.0 }, Square { side: 2.0 }];
    println(shapes);
}
```

## Step 2: Method calls on interface values
Kind: read

`s.area()` on a `Shape` runs the `area` of the type inside it.
The loop on lines 19 to 21 adds up `s.area()` for a circle and a square, each with its own `area`.
A `Shape` has only its methods, though: `shapes[0].r` would be E0410, "no field `r` on `Shape`".
Press Run.

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Square {
    fun area(self): f64 = self.side * self.side;
}

fun main() {
    let shapes: Shape[] = [Circle { r: 1.0 }, Square { side: 2.0 }];
    let mut total = 0.0;
    for s of shapes {
        total += s.area();
    }
    println(total);
}
```

Output:

```text
7.0
```

## Step 3: Type patterns
Kind: fix (start gives E0417 "non-exhaustive match: `_` not covered", help "add the missing arms, or `_ => …`")

To reach the value inside a `Shape`, `match` on its type.
`c: Circle` on line 18 matches when `s` holds a `Circle`, and names it `c`, a `Circle` with its fields.
`_: Square` on line 19 matches a square without naming it, since its arm doesn't need it.
Press Run.

`lughac` stops at line 17 with E0417, "non-exhaustive match: `_` not covered".
Any type that meets `Shape` could be inside, even one written later, so the `match` needs a `_` arm even with an arm for each type here:

```lugha {20}
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Square {
    fun area(self): f64 = self.side * self.side;
}

fun kind(s: Shape): string {
    match s {
        c: Circle => "a circle of radius {c.r}",
        _: Square => "a square",
        _ => "something else",
    }
}

fun main() {
    println(kind(Circle { r: 2.0 }));
    println(kind(Square { side: 1.0 }));
}
```

Add the `_` arm as line 20; Solve does it for you.

## Step 4: Interface conversion
Kind: fix (start gives E0403 "expected Shape[], found Circle[]")

The conversion in the first step happens to a value, never to an array or an `Option` around it.
`total` on line 16 takes a `Shape[]`, and line 20 passes `circles`, a `Circle[]`.
Press Run.

The call on line 20 is E0403, "expected Shape[], found Circle[]".
An array's type is fixed where it's built, so make `circles` a `Shape[]` there:

```lugha {19}
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

    fun area(self): f64 = self.side * self.side;

    let circles: Shape[] = [Circle { r: 1.0 }, Circle { r: 2.0 }];
    println(total(circles));
}
```
