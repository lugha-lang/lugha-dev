## Step 1: String interpolation
Kind: read

A string can hold values: line 4 puts `name` and `points` inside it, in braces.
Each pair of braces is replaced by the value of what's inside it, written the way `println` would print it.
The braces can hold any expression, like `points * 2` on line 5.
Press Run.

```lugha
fun main() {
    let name = "Amina";
    let points = 7;
    println("{name} has {points} points");
    println("doubled: {points * 2}");
}
```

Output:

```text
Amina has 7 points
doubled: 14
```

## Step 2: Format specifiers
Kind: read

A `:` after the expression starts a specifier, which changes how the value is written.
Line 4 adds `:.2` to `share`, which asks for two decimals.
Will `.2` round `0.666…` or cut it off?

It rounds, to `0.67`, and a precision like `.2` works only on floats.
Lines 5 and 6 ask for a width of 6: `>` puts `42` at the end of its six characters and `<` at the start.
A `0` before the width pads with zeros, as on line 7, and on line 8 `x` writes the number in hex and `#` puts `0x` in front.

```lugha
fun main() {
    let share = 2.0 / 3.0;
    println("{share}");
    println("{share:.2}");
    println("[{42:>6}]");
    println("[{42:<6}]");
    println("{7:03}");
    println("{255:#x}");
}
```

Output:

```text
0.6666666666666666
0.67
[    42]
[42    ]
007
0xff
```

## Step 3: Escaping braces
Kind: fix (start gives E0301 "cannot find `name` in this scope")

Since braces interpolate, printing a brace itself takes something else.
Line 2 means to print the text `{name}`, braces and all.
Every `{` in a string starts an interpolation, so `lughac` looks for a variable called `name` and gives E0301, "cannot find `name` in this scope".
Two braces in a row make one literal brace, `{{` for `{` and `}}` for `}`:

```lugha {2}
fun main() {
    println("write {{name}} to put a value in");
}
```

Double both braces on line 2, or press Solve.


## Step 4: String concatenation
Kind: fix (start gives E0404 "cannot apply `+` to string and i64")

Braces aren't the only way to build a string: `+` joins two strings into a new one.
Line 4 uses it to build a sentence from `name`, `" has "` and `points`.
Will `+` take the number too?

Line 4 stops at E0404, "cannot apply `+` to string and i64".
`+` only joins strings, and a number never turns into one by itself.
Put the number in braces inside the string instead:

```lugha {4}
fun main() {
    let name = "Amina";
    let points = 7;
    let line = name + " has {points}";
    println(line);
}
```

## Step 5: String length
Kind: read

A string's `.len`, like an array's, is read without parentheses, and line 3 prints it for `Zoë`.
What will it print for a name of three letters?

It prints `4`, because `.len` counts bytes and `ë` takes two of them in UTF-8.
Line 4 counts characters with `char_count()`, a method you call, so it prints `3`.

```lugha
fun main() {
    let name = "Zoë";
    println(name.len);
    println(name.char_count());
}
```

Output:

```text
4
3
```

## Step 6: Bytes
Kind: read

Indexing a string reads bytes as well, the same units `.len` counts.
Line 3 prints `word[0]`, the first byte of `"hi"`.
Will it print `h`?

It prints `104`, the number of the byte that encodes `h`, because `word[0]` is a `u8`.
A `for … of` loop over a string, as on line 4, goes through its bytes the same way.

```lugha
fun main() {
    let word = "hi";
    println(word[0]);
    for b of word {
        println(b);
    }
}
```

Output:

```text
104
104
105
```

## Step 7: String methods
Kind: read

Beyond single bytes, most work on a string goes through its methods.
Line 3 takes the spaces off both ends with `trim` and cuts the result at each comma with `split`, which gives a `string[]`.
`join` on line 5 puts an array of strings back together with a separator between them.
`contains` and `starts_with` give a `bool`, and `lines` on line 8 splits at each `\n`.
None of them changes the string: `line` on line 7 still has its spaces, so it's trimmed again.

```lugha
fun main() {
    let line = "  milk,bread,eggs  ";
    let items = line.trim().split(",");
    println(items);
    println(items.join(" + "));
    println(line.contains("bread"));
    println(line.trim().starts_with("milk"));
    println("one\ntwo".lines());
}
```

Output:

```text
["milk", "bread", "eggs"]
milk + bread + eggs
true
true
["one", "two"]
```

## Step 8: Slicing
Kind: read

`slice(from, to)` gives the part of a string between two offsets, counted in bytes like `.len`.
In `Zoë`, `Z` and `o` are bytes 0 and 1, and `ë` takes bytes 2 and 3, so line 4's `slice(2, 4)` gives `ë`.
`slice` checks only that the offsets are inside the string, so `slice(0, 3)` would give `Z`, `o` and half of `ë`, which isn't a whole character.

```lugha
fun main() {
    let name = "Zoë";
    println(name.slice(0, 2));
    println(name.slice(2, 4));
}
```

Output:

```text
Zo
ë
```

## Step 9: The char type
Kind: read

A single character has its own type, `char`, and `grade < 'c'` on line 3 compares code points.
Methods such as `is_digit()` and `to_upper()` work on it.
Will `to_upper()` work on any letter?

Only within ASCII and Latin-1, so `'é'` on line 6 becomes `'É'` and the Cyrillic `'ж'` on line 8 comes back unchanged.
`'ß'` on line 7 is in Latin-1 but keeps its case too, because its capital isn't.

```lugha
fun main() {
    let grade = 'b';
    println(grade < 'c');
    println('7'.is_digit());
    println(grade.to_upper());
    println('é'.to_upper());
    println('ß'.to_upper());
    println('ж'.to_upper());
}
```

Output:

```text
true
true
B
É
ß
ж
```
