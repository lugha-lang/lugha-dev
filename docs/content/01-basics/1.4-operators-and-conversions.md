# 1.4 Operators and conversions

## Objectives

After this lesson the learner can:

- Use `+ - * / %` on two numbers of the same type, and get that type. [L693]
- Know integer division drops the fraction toward zero, and `%` takes the sign of the left side. [L893]
- Write a float where a float is expected: `let e: f64 = 5;` and `total / 2.0` with an `i64` `total` are refused; `5.0` and `total as f64` are fine. [L678, L686, L693]
- Convert with `as`, and know what it does: float to integer drops the fraction, narrowing keeps what fits, and a float too big for an integer saturates. [L724]
- Use comparisons and `&& || !`, and know `&&` and `||` stop as soon as the answer is known. [L470–488, L695–698]
- Surprises:
  - Integer overflow stops the program (`panic: integer overflow`, exit 101); it never wraps. [L893]
  - Integer division by zero stops the program; a float divided by zero gives `inf`. [L893, L967]
  - `18 <= age < 65` is an error (E0203); write it with `&&`. [L470]

(Left out after testing: "`-x` works on `i32`, `i64`, `f32`, `f64` only". `-x` on an `i8` is E0404, which looks like a gap in lughac rather than a rule to teach; it's in the Notes for `../lugha`.)

## Step 1: Integer division
Kind: read

In the last lesson `height * 300` had to fit a `u8`, because arithmetic works on two numbers of the same type and gives that type.
So dividing two whole numbers gives a whole number, and line 2 prints `3`.
Before you run it, decide: will `-7 / 2` on line 3 print `-3` or `-4`?
Then press Run.

It prints `-3`, so if you said `-4`, you were expecting division to round down.
Lugha drops the fraction toward zero instead, and `%` on line 4 takes its sign from the left side, giving `-1`.
The half survives only when both sides are floats, as on line 5.

```lugha
fun main() {
    println(7 / 2);
    println(-7 / 2);
    println(-7 % 2);
    println(7.0 / 2.0);
}
```

Output:

```text
3
-3
-1
3.5
```

## Step 2: Conversion with as
Kind: fix (start gives E0401 "float literal where i64 expected")

So to get half of `total`, which is an `i64`, line 3 divides it by `2.0`.
Press Run.

`lughac` refuses it with E0401.
The `2.0` takes its type from `total` on the other side of the `/`, as the `300` did in the last lesson, and a float can't be an `i64`.
A whole number never becomes a float on its own, which is also why `let price: f64 = 5;` is refused and `5.0` isn't.
Write `total as f64` to turn `total` into a float before dividing:

```lugha {3}
fun main() {
    let total = 7;
    let half = total as f64 / 2.0;
    println(half);
}
```

Change line 3 and run again, or press Solve.

Start:

```lugha
fun main() {
    let total = 7;
    let half = total / 2.0;
    println(half);
}
```

Solution:

```lugha
fun main() {
    let total = 7;
    let half = total as f64 / 2.0;
    println(half);
}
```

Output (solution):

```text
3.5
```

## Step 3: Lossy conversions
Kind: read

`as` never fails, so a value that doesn't fit its new type comes out changed.
Line 2 turns `3.99` into an `i64`.
Will you get `3` or `4`?

It's `3`, and if you said `4`, you were expecting `as` to round.
A float becomes an integer by dropping its fraction, as line 3 shows for a negative too.
Line 4 narrows `300` into a `u8` by keeping only its lowest 8 bits, so it wraps around to `44`.
Line 5 is a float too big for an `i64`, and a float doesn't wrap: it stops at the largest `i64`.

```lugha
fun main() {
    println(3.99 as i64);
    println(-3.99 as i64);
    println(300 as u8);
    println(1.0e20 as i64);
}
```

Output:

```text
3
-3
44
9223372036854775807
```

## Step 4: Integer overflow
Kind: read

Only `as` wraps a whole number around.
Arithmetic doesn't: when a result won't fit, the program stops instead.
`level` is a `u8` holding 250, so line 3 prints `255`, its largest value, and line 4 adds 10.
Press Run.

After `255`, the program panics with `integer overflow`, names the line and column, and exits with code 101.
Dividing a whole number by zero stops a program the same way, while a float divided by zero doesn't stop it: `1.0 / 0.0` gives `inf`.

```lugha
fun main() {
    let level: u8 = 250;
    println(level + 5);
    println(level + 10);
}
```

Output (exit code 101):

```text
255
panic: integer overflow at src/main.la:4:19
```

## Step 5: Comparison and logical operators
Kind: fix (start gives E0203 "`<=` and `<` can't be chained")

Comparisons give a `bool`, and line 4 checks that `age` is between 18 and 65 in one go.
Press Run.

If you expected it to run, you were expecting `18 <= age < 65` to mean two comparisons at once.
In Lugha comparisons don't chain, so `lughac` stops at E0203, and the two halves are joined with `&&`:

```lugha {4}
fun main() {
    let age = 30;
    let member = false;
    println(18 <= age && age < 65);
    println(!member || age > 60);
}
```

Rewrite line 4 as two comparisons and run it again.
Line 5 uses `!` for not and `||` for or, and `&&` and `||` stop as soon as the answer is known.
So in `zero != 0 && 10 / zero > 1`, the kind of division that panicked in the last step never runs when `zero` is 0.

Start:

```lugha
fun main() {
    let age = 30;
    let member = false;
    println(18 <= age < 65);
    println(!member || age > 60);
}
```

Solution:

```lugha
fun main() {
    let age = 30;
    let member = false;
    println(18 <= age && age < 65);
    println(!member || age > 60);
}
```

Output (solution):

```text
true
true
```

## Notes

- Spec lines relied on: operators on two numbers of the same type [L693]; integer overflow panics, `/` and `%` panic on a zero divisor, `%` takes the dividend's sign [L893]; float division by zero gives infinity [L967]; `as` between numeric types, float to integer truncates toward zero and saturates, narrowing truncates [L724]; an integer literal never becomes a float [L678]; comparisons don't chain (E0203), `&&` and `||` short-circuit [L470–475]; panics print `panic: <message> at <file>:<line>:<col>` and exit 101 [L1051].
- Every program was run in the sandbox (pinned lughac m159). Also tested: `10 / zero` with `zero = 0` panics "division by zero" (exit 101) and `1.0 / 0.0` prints `inf`; `zero != 0 && 10 / zero > 1` prints `false`; `let price: f64 = 5;` is E0401 "integer literal where f64 expected". The spec doesn't say in words how integer `/` rounds; `-7 / 2` printing `-3` is the run's result.
- For `../lugha`: unary `-` on an `i8` is E0404 "cannot apply `-` to i8". The spec's operator table lists unary `-` only for `i32`, `i64`, `f32`, `f64`, so it matches the spec, but `i8` and `i16` are signed, so this looks like a gap.

All three picked "`as` changes a value only because you asked; arithmetic never does." as the most machine-made line; all three found "keeps only what fits" (`300 as u8` → 44) too vague, and one read it as contradicting "a whole number never wraps". Some asked about `u8`, exponents and `i64.MAX`, which 1.2 and 1.3 teach (readers see one lesson only).
- Voice reviewer, first draft: steps 3 and 4 contradicted each other on wrapping; "a float divided by zero gives `inf`" was broader than the facts (`0.0 / 0.0` is NaN); `!` was in the objectives but never used; step 2 explained the error by `total` when lughac points at `2.0`; noun title on step 3; summing-up lines.
