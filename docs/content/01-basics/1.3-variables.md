# 1.3 Variables

## Objectives

After this lesson the learner can:

- Declare with `let`, and use the name where the value would go. [L420]
- Know variables can't change unless declared `let mut` (E0501). [L251, L872]
- Let the type be worked out, or write it after a colon. [L672–676]
- Know how a number literal gets its type: from what's around it (an annotation, the other operand), else `i64` or `f64`. [L676–677]
- Know assignment is a statement with no value, so `a = b = 0` is E0204 (moved from 2.1, 2026-11-14). [L490]
- Shadow a variable with a second `let`, and know that on its right-hand side the name still means the old one. [L979]
- Declare a constant with `const NAME: T = value;` outside any function, and know there are no other variables outside functions. [L1130, L1128]
- Surprises:
  - A number that doesn't fit its type is a compile error (`let d: u8 = 300;`). [L678]
  - A whole number never becomes a float: `let e: f64 = 5;` is an error. [L678, L686] (Stated here; the fix step is in 1.4, beside `as`.)

(Moved after planning: "inference is local, so parameters, return types and fields are always written" goes to 2.2 Functions, where there are parameters to show it.)

## Step 1: Variable declaration
Kind: read

Every value so far went straight into `println`.
`let` gives a value a name instead: line 2 gives `7` the name `width`, and line 3 gives `3` the name `height`, writing its type after a colon.
Press Run.

Line 4 uses the names where the values would go, and prints `21`.
A `let` doesn't need its type written, because `lughac` takes it from the value, as it did for `width`.

```lugha
fun main() {
    let width = 7;
    let height: i64 = 3;
    println(width * height);
}
```

Output:

```text
21
```

## Step 2: Mutable variables
Kind: fix (start gives E0501 "cannot assign to `count`: it is not mutable")

Once `let` has named a value, can the name be given another?
Line 3 tries to add 1 to `count`.
Press Run.

It doesn't compile, and `lughac` reports E0501.
If you expected it to run, you were expecting `let` to declare a variable that can change.
In Lugha a variable keeps the value it was given unless it's declared `let mut`:

```lugha {2}
fun main() {
    let mut count = 0;
    count = count + 1;
    println(count);
}
```

Add `mut` on line 2 and run again.

Start:

```lugha
fun main() {
    let count = 0;
    count = count + 1;
    println(count);
}
```

Solution:

```lugha
fun main() {
    let mut count = 0;
    count = count + 1;
    println(count);
}
```

Output (solution):

```text
1
```

## Step 3: Assignment
Kind: fix (start gives E0204 "assignment is a statement, not an expression")

Both `a` and `b` are `let mut` this time, and line 4 tries to set both to `0` in one go, with `a = b = 0`.
Will that work?

`lughac` refuses it with E0204, "assignment is a statement, not an expression".
An assignment is only ever a statement, with no value at all, so `b = 0` has nothing for `a` to take:

```lugha {4,5}
fun main() {
    let mut a = 1;
    let mut b = 2;
    a = 0;
    b = 0;
    println(a + b);
}
```

Split line 4 into two assignments, one per line.

Start:

```lugha
fun main() {
    let mut a = 1;
    let mut b = 2;
    a = b = 0;
    println(a + b);
}
```

Solution:

```lugha
fun main() {
    let mut a = 1;
    let mut b = 2;
    a = 0;
    b = 0;
    println(a + b);
}
```

Output (solution):

```text
0
```

## Step 4: Number literal types
Kind: fix (start gives E0402 "integer literal out of range for u8", help "u8 holds 0 to 255")

A whole number takes its type from what's around it.
Line 2 asks for nothing, so its `7` is an `i64`, the type a whole number gets when nothing decides, and a number with a `.` gets `f64`.
Line 3 asks for a `u8`, a whole number from 0 to 255, and line 4 multiplies `height` by `300`.
Press Run.

`lughac` refuses line 4 with E0402.
The `300` takes its type from `height` on the other side of the `*`, and `300` doesn't fit in a `u8`:

```lugha {4}
fun main() {
    let width = 7;
    let height: u8 = 7;
    let doubled = height * 30;
    println(width);
    println(doubled);
}
```

Change `300` to `30` and run again, or press Solve.
A whole number never turns into a float, though, so a float is always written with its `.`, as in `5.0`.

Start:

```lugha
fun main() {
    let width = 7;
    let height: u8 = 7;
    let doubled = height * 300;
    println(width);
    println(doubled);
}
```

Solution:

```lugha
fun main() {
    let width = 7;
    let height: u8 = 7;
    let doubled = height * 30;
    println(width);
    println(doubled);
}
```

Output (solution):

```text
7
210
```

## Step 5: Shadowing
Kind: read

There's another way to give a name a new value without `mut`: declare it again.
Line 3 declares `score` a second time, from the old `score`.
Will it compile, and if so, what will line 4 print?

It compiles and prints `15`.
If you expected an error, you were expecting the second `let score` to clash with the first.
A new `let` hides the old variable once its own declaration ends, which is called shadowing, so after its `=`, `score` still means the old one.
Line 5 shadows it again with a string, which `mut` could never do: assigning changes a variable's value but never its type, while shadowing makes a new variable.

```lugha
fun main() {
    let score = 10;
    let score = score + 5;
    println(score);
    let score = "fifteen";
    println(score);
}
```

Output:

```text
15
fifteen
```

## Step 6: Constants
Kind: read

A value the whole program shares is a constant, declared with `const` outside any function, as on line 1.
Its type must be written, and leaving it out is an error.
Press Run.

Line 5 reads `MAX_SCORE` like a variable, but nothing can assign to it, and trying is E0501.
`let` is refused outside a function, so a value the whole program shares is always a `const`, and its value is fixed for the whole run.

```lugha
const MAX_SCORE: i64 = 100;

fun main() {
    let score = 40;
    println(MAX_SCORE - score);
}
```

Output:

```text
60
```
