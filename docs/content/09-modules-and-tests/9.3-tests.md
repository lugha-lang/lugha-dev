## Step 1: Test functions
Kind: read (a test step: Test, all pass)

A test is a function with `@test` on the line before it, as on line 3 of `test/shapes_test.la`.
It takes no parameters and returns nothing; a test that does either is E0434.
`assert` on line 6 panics unless what it's given is true, and a panic fails the test.
`lugha.toml` names the package `geometry`, so line 1 imports `shapes` as `geometry.shapes`.
Press Test.
The Tests tab names each test by its file's path and its own name, `test.shapes_test.area_of_three`.

`src/main.la`:

```lugha
import shapes;

fun main() {
    let s = shapes.Square { side: 3.0 };
    println(shapes.area(s));
}
```

`src/shapes.la`:

```lugha

```

`test/shapes_test.la`:


## Step 2: assert_eq and assert_ne
Kind: fix (a test step; start fails area_of_three)

`assert` only says "assertion failed", so line 6 of `test/shapes_test.la` uses `assert_eq(a, b)` instead, which fails unless `a` and `b` are equal.
`assert_ne` on line 13 fails if they are equal.
When they fail, `assert_eq` prints both values, the first as left, and `assert_ne` the one they share.
Press Test.

`area_of_three` fails with "assert_eq failed: left 6.0, right 9.0": `area` gave 6.0, and the test expects 9.0.
Line 3 of `shapes.la` multiplies the side by 2.0 instead of by itself.
The fixed `shapes.la`:

```lugha {3}
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;
```

Change `2.0` to `s.side` on line 3, or press Solve, and press Test again.

## Step 3: Running tests
Kind: fix (a test step; start fails largest_of_none)

`largest` in `shapes.la` should give the largest of an array of squares, or `None` for an empty one, and the test file checks both.
Press Test.

`largest_of_none` fails with a panic, "index out of bounds", but each test runs as its own process, so `largest_of_two` still passes after it.
The last line, "2 tests: 1 passed, 1 failed", counts the whole run.
Line 6 of `shapes.la` reads `squares[0]` before checking that there is one.
Run builds the program without its tests, so only Test runs them.
The fixed `shapes.la`:

```lugha {6,7,8}
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;

fun largest(squares: Square[]): Option<Square> {
    if squares.len == 0 {
        return None;
    }
    let mut best = squares[0];
    for s of squares {
        if s.side > best.side {
            best = s;
        }
    }
    return Some(best);
}
```

Add the check for `squares.len == 0` at the top of `largest` and press Test again; Solve does the same.

## Notes

- Spec lines relied on (m159): `@test` before a top-level `fun`, no parameters, returns nothing (E0434), tests in their own files through imports [L1791]; `assert`, `assert_eq` ("assert_eq failed: left <a>, right <b>"), `assert_ne` ("assert_ne failed: both <a>") in the intrinsics table; each test its own process, so a panic fails only that test [L1793]; output lines and summary [L1794]; `build` and `run` leave tests out [L1791]; a program under its package's manifest in `test/` is a module of that package [L1372].
- Every program ran in the sandbox (pinned lughac m159) through the local API, Run and the test job, with its own `lugha.toml` (`geometry`). The Tests blocks are the API's JSON (names, status, message, at) in the Tests tab's format (`lib/testtext.ts`).
- Test names are `test.shapes_test.…` as the API reports them; `start_failing` matches their last part.
- Step 2's `assert_ne` test passes on the start too (2.0 × 2 and 2.0 × 3 differ), so only `area_of_three` fails.
- Arrays' length is `.len`, a field, not a method (spec L645; `len()` is E0415).
