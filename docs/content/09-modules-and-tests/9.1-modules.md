## Step 1: Multiple files
Kind: read

A program can be split across several files, and each file is a module named by its path from `main.la`'s folder, without `.la`.
`src/shapes.la`, in the file list, is the module `shapes`: it declares `Square` and two functions.
Line 1 of `main.la`, `import shapes;`, loads it, and the rest of `main` uses what `shapes.la` declares.
Press Run.

`src/main.la`:

```lugha
import shapes;

fun main() {
    let s = shapes.Square { side: 3.0 };
    println(shapes.describe(s));
    println(shapes.area(s));
}
```

`src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;

fun describe(s: Square): string = "a square of side {s.side}";
```

Output:

```text
a square of side 3.0
9.0
```

## Step 2: import
Kind: fix (start gives E0305 "cannot find type `shapes.Square`" on line 2, and E0301 "cannot find `shapes` in this scope" on lines 3 and 4)

`main.la` has lost its `import`, though `shapes.la` is still there.
Press Run.

`lughac` stops with E0305 for the type on line 2, "cannot find type `shapes.Square`", and E0301 for the names on lines 3 and 4.
Having `shapes.la` in the project isn't enough: `main.la` needs its own `import`, and that binds the name `shapes`.
Every item from the module is then written with `shapes.` in front, as `main` already does.
The fixed `main.la`:

`src/main.la`:

```lugha {1}
import shapes;

fun main() {
    let s = shapes.Square { side: 3.0 };
    println(shapes.describe(s));
    println(shapes.area(s));
}
```

Add `import shapes;` as line 1; Solve does it for you.

## Step 3: Import aliases
Kind: fix (start gives E0305 "cannot find type `shapes.Square`" on line 4)

The name an import binds can be changed: `import shapes as geo;` on line 1 binds the module as `geo`, which is shorter to write.
Line 4 still writes `shapes.Square`.
Press Run.

That's E0305: with `as geo`, only `geo` is bound in this file, and `shapes` isn't.
The fixed `main.la`:

`src/main.la`:

```lugha {4}
import shapes as geo;

fun main() {
    let s = geo.Square { side: 3.0 };
    println(geo.area(s));
}
```

Change `shapes.Square` to `geo.Square` on line 4, or press Solve.

Start:

`src/main.la`:

## Step 4: Named imports
Kind: read

An import can also list items after the module's name, and those are written without the module's name in front.
Line 1 lists `Square`, so line 4 builds one as plain `Square`.
`area as square_area` brings in `area` under the name `square_area`, which line 5 calls.
`shapes.describe` on line 6 still works, since the import binds `shapes` as well.
Press Run.

`src/main.la`:

```lugha
import shapes { Square, area as square_area };

fun main() {
    let s = Square { side: 3.0 };
    println(square_area(s));
    println(shapes.describe(s));
}
```

`src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;

fun describe(s: Square): string = "a square of side {s.side}";
```

Output:

```text
9.0
a square of side 3.0
```

- Every program was run in the sandbox (pinned lughac m159) through the local API, with both files.
- Folders under `src/` aren't allowed in steps (PRP-005), so `import shapes.circle;` isn't shown; step 1 names a module by its path, which covers it.
- Visibility (`public`, package, private) is 9.2's; everything here is in one package, where nothing needs `public`.
