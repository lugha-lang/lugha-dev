## Step 1: Closures
Kind: fix (start gives E0412 "can't infer the type of parameter `x`", help "write it: `x: i64`, or pass the closure where a function type is expected")

A closure is a function written in place, without a name: `fun(x) = x * 2` on line 4 doubles its argument.
Line 4 passes it to `apply`, so `x` takes its type from `apply`'s parameter, a `fun(i64): i64`.
Line 5 stores one in `add_ten`, where nothing says what `x` is.

That's E0412, "can't infer the type of parameter `x`".
Write the parameter's type, as a named function has it; the return type can be written too.
A longer body goes in braces, as in `fun(n: i64): string { … }`, and a closure that uses `return` needs its return type written.

```lugha {5}
fun apply(f: fun(i64): i64, x: i64): i64 = f(x);

fun main() {
    println(apply(fun(x) = x * 2, 21));
    let add_ten = fun(x: i64): i64 = x + 10;
    println(add_ten(5));
}
```

Add the types on line 5, or press Solve.

Start:

```lugha
fun apply(f: fun(i64): i64, x: i64): i64 = f(x);

fun main() {
    println(apply(fun(x) = x * 2, 21));
    let add_ten = fun(x) = x + 10;
    println(add_ten(5));
}
```

Solution:

```lugha
fun apply(f: fun(i64): i64, x: i64): i64 = f(x);

fun main() {
    println(apply(fun(x) = x * 2, 21));
    let add_ten = fun(x: i64): i64 = x + 10;
    println(add_ten(5));
}
```

```text

15
```

## Step 2: Capture by copy
Kind: read

A closure can use the variables around it.
`scale` on line 3 uses `rate`, which is `2` at that point, and line 4 changes `rate` to `7` afterwards.
What will `scale(5)` on line 5 print?
Press Run.

It prints `10`: `scale` copied `rate` when line 3 made it, so line 4's change doesn't reach it, though line 6 shows `rate` is `7` now.

```lugha
fun main() {
    let mut rate = 2;
    let scale = fun(x: i64): i64 = x * rate;
    rate = 7;
    println(scale(5));
    println(rate);
}
```

Output:

```text
10
7
```

## Step 3: Counters with Ref
Kind: fix (start gives E0511 "can't change `count`: closures capture by copy", help "the closure has its own copy; return a new value instead")

A closure never changes the variables it copies.
`tick` on line 3 tries to add `1` to `count`.

Line 3 is E0511, "can't change `count`: closures capture by copy".
Its help says to return a new value instead.
To share a count, make it a `Ref`: the closure copies the handle, and both reach the same box, as in the Ref lesson:

```lugha {2,3,6}
fun main() {
    let count = Ref.new(0);
    let tick = fun() { count.set(count.get() + 1); };
    tick();
    tick();
    println(count.get());
}
```

Make `count` a `Ref` on lines 2, 3 and 6, or press Solve.

Start:

```lugha
fun main() {
    let mut count = 0;
    let tick = fun() { count += 1; };
    tick();
    tick();
    println(count);
}
```

Solution:

```lugha
fun main() {
    let count = Ref.new(0);
    let tick = fun() { count.set(count.get() + 1); };
    tick();
    tick();
    println(count.get());
}
```

Output (solution):

```text
2
```

## Step 4: Ref.update
Kind: read

`update` takes a function, and a closure can be written right there instead of a named one like `add_one`.
Line 3 triples what's in `total` with `fun(n) = n * 3`, and `n` takes its type from `update`'s parameter, a `fun(i64): i64`, as `x` did from `apply`'s.
Press Run.

```lugha
fun main() {
    let total = Ref.new(10);
    total.update(fun(n) = n * 3);
    println(total.get());
}
```

Output:

```text
30
```

## Step 5: map and and_then
Kind: read

`map` on an `Option` gives a new `Some` holding what the closure returns, and leaves a `None` as it is, as lines 2 and 3 show.
On a `Result`, `map` works on an `Ok` and leaves an `Err` as it is, on lines 6 and 7, as `map_err` did the other way.
`and_then` takes a closure that returns an `Option` or a `Result` itself, so on lines 8 and 9 it turns a success into a failure.
Line 9 writes its closure's return type, because `lughac` can't work it out there.
Press Run.

```lugha
fun main() {
    println(parse_i64("21").map(fun(n) = n * 2));
    println(parse_i64("x").map(fun(n) = n * 2));
    let good: Result<i64, string> = Ok(4);
    let bad: Result<i64, string> = Err("no");
    println(good.map(fun(n) = n + 1));
    println(bad.map(fun(n) = n + 1));
    println(parse_i64("-3").and_then(fun(n) = if n > 0 { Some(n) } else { None }));
    println(good.and_then(fun(n: i64): Result<i64, string> = if n > 9 { Ok(n) } else { Err("too small") }));
}
```

Output:

```text
Some(42)
None
Ok(5)
Err("no")
None
Err("too small")
```

## Step 6: Closures and recursion
Kind: fix (start gives E0301 "cannot find `fact` in this scope")

A closure has no name of its own, so it can't call itself.
`fact` on line 2 is only the variable that will hold the closure, so the `fact(n - 1)` inside it refers to nothing.

`lughac` reports E0301, "cannot find `fact` in this scope".
A named function can call itself, so write `fact` as one:

```lugha {1}
fun fact(n: i64): i64 = if n <= 1 { 1 } else { n * fact(n - 1) };

fun main() {
    println(fact(5));
}
```

Turn the closure into a named function, or press Solve.

Start:

```lugha
fun main() {
    let fact = fun(n: i64): i64 = if n <= 1 { 1 } else { n * fact(n - 1) };
    println(fact(5));
}
```

Solution:

```lugha
fun fact(n: i64): i64 = if n <= 1 { 1 } else { n * fact(n - 1) };

fun main() {
    println(fact(5));
}
```

Output (solution):

```text
120
```
