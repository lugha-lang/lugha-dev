## Step 1: Option instead of null
Kind: read

A value that may be missing has the type `Option`: either `Some` with the value inside, or `None`.
There's no null in Lugha, so an `Option` is how a missing value is written.
`find` on line 1 looks for a name and gives back its position, so its return type is `Option<i64>`.
Line 4 returns `Some(i)` when the name is found, and line 7 gives `None` once the loop ends without it.
`Some` and `None` are written on their own, without `Option.` in front.
Press Run.

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main() {
    let names = ["Ann", "Ben", "Cy"];
    println(find(names, "Ben"));
    println(find(names, "Dee"));
}
```

Output:

```text
Some(1)
None
```

## Step 2: Matching on Option
Kind: read

`Option` is an enum, so a `match` gets at the value inside, as it did for `Shape`.
Line 13 matches on what `find` gives back for each name.
`Some(i)` on line 14 names the position `i`, and `None` on line 15 covers a name that isn't there.
Leaving out the `None` arm is E0417, so the program has to say what happens when a name isn't found.
Press Run.

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main() {
    let names = ["Ann", "Ben", "Cy"];
    for wanted of ["Ben", "Dee"] {
        match find(names, wanted) {
            Some(i) => println("{wanted} is at {i}"),
            None => println("{wanted} isn't there"),
        }
    }
}
```

Output:

```text
Ben is at 1
Dee isn't there
```

## Step 3: Typing None

Line 5 sets it to `Some(n)` once it does.

fun main() {

## Step 4: unwrap_or, is_some and is_none
Kind: read

`is_none()` on line 12 and `is_some()` on line 13 say which variant an `Option` is, as a `bool`, without a `match`.
`unwrap_or(-1)` gives the value inside a `Some`, or `-1` for a `None`, so line 15 prints `-1` for the missing name.
Press Run.

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main() {
    let names = ["Ann", "Ben", "Cy"];
    println(find(names, "Dee").is_none());
    println(find(names, "Ben").is_some());
    println(find(names, "Ben").unwrap_or(-1));
    println(find(names, "Dee").unwrap_or(-1));
}
```

Output:

```text
true
true
1
-1
```

## Step 5: Parsing numbers
Kind: fix (start gives E0404 "cannot apply `+` to `Option<i64>` and `i64`")

`parse_i64` reads a whole number from a string, with an optional `-` in front.
Its result is an `Option<i64>`: `Some` with the number, or `None` for text such as `"4.5"` or `"nine"`.
Line 4 adds `1` to what it gave back.

That's E0404, "cannot apply `+` to `Option<i64>` and `i64`", because the number is still inside the `Option`.
`unwrap_or(0)` on line 3 takes it out, with `0` standing in when the text isn't a number:

```lugha {3}
fun main() {
    let typed = "41";
    let n = parse_i64(typed).unwrap_or(0);
    println(n + 1);
}
```

Add `.unwrap_or(0)` on line 3, or press Solve.

Start:

```lugha
fun main() {
    let typed = "41";
    let n = parse_i64(typed);
    println(n + 1);
}
```

Solution:

```lugha
fun main() {
    let typed = "41";
    let n = parse_i64(typed).unwrap_or(0);
    println(n + 1);
}
```

Output (solution):

```text
42
```

## Step 6: pop
Kind: read

`pop` removes the last element of an array and returns it as `Some`, or `None` when the array is empty.
`stack` on line 2 holds two numbers, and lines 3 to 5 pop three times.
What will the third `pop` print?
Press Run.

It prints `None`: popping an empty array isn't an error, and line 6 goes on to print the array, empty now.
Like `push`, `pop` changes the array, so `stack` needs `let mut`.

```lugha
fun main() {
    let mut stack = [1, 2];
    println(stack.pop());
    println(stack.pop());
    println(stack.pop());
    println(stack);
}
```

Output:

```text
Some(2)
Some(1)
None
[]
```

## Step 7: Checked arithmetic
Kind: fix (start panics with `integer overflow`, exit code 101)

This is the program from Integer overflow, where `level + 10` stopped the program because 260 doesn't fit in a `u8`.
`checked_add` does the same addition and gives an `Option`: `Some` with the sum, or `None` where `+` would panic.

With `checked_add` in both places, an overflow gives a `None` the program can check, instead of stopping it:

```lugha {3,4}
fun main() {
    let level: u8 = 250;
    println(level.checked_add(5));
    println(level.checked_add(10));
}
```
