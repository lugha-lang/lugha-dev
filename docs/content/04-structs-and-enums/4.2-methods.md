## Step 1: Methods
Kind: read

A method is a function attached to a type, declared inside an `impl` block for it, as on lines 3 to 5.
Its first parameter is `self`, the value it's called on, written without a type.
Line 9 calls it with a dot, `p.length_squared()`, so `self` is `p`.
Press Run.

```lugha
struct Point { x: i64, y: i64 }

impl Point {
    fun length_squared(self): i64 = self.x * self.x + self.y * self.y;
}

fun main() {
    let p = Point { x: 3, y: 4 };
    println(p.length_squared());
}
```

Output:

```text
25
```

## Step 2: mut self methods
Kind: fix (start gives E0501 "cannot call `mut self` method `shift` on `p`: it is not mutable", help "make it mutable: `let mut p`")

`self` is read-only, like any parameter, so a method that changes the value it's called on takes `mut self` instead, as `shift` does on line 4.
Line 11 calls `shift` on `p`, and `p` has no `mut`.
Will the call go through, since `shift` already takes `mut self`?

It does: E0501, "cannot call `mut self` method `shift` on `p`: it is not mutable".
A `mut self` method changes the caller's own value, so `p` needs `let mut`, as it did for field assignment:

```lugha {10}
struct Point { x: i64, y: i64 }

impl Point {
    fun shift(mut self, dx: i64) {
        self.x += dx;
    }
}

fun main() {
    let mut p = Point { x: 3, y: 4 };
    p.shift(10);
    println(p);
}
```

Add `mut` on line 10.

Start:

```lugha

    fun shift(mut self, dx: i64) {
        self.x += dx;
    }
}

```

Solution:

```lugha

    fun shift(mut self, dx: i64) {
        self.x += dx;
    }
}

    let mut p = Point { x: 3, y: 4 };

    println(p);
}
```


## Step 3: Associated functions and Self
Kind: read

A function in an `impl` without `self` is an associated function.
It belongs to the type rather than a value, and is called on the type's name, as `Point.new(3, 4)` on line 10.
`new` here builds a `Point` from its two fields.
Inside the `impl`, `Self` stands for `Point`, both as a type and before a struct literal, as on line 4.
`origin` on line 6 calls `new` the same way, as `Self.new(0, 0)`.

```lugha
struct Point { x: i64, y: i64 }

impl Point {
    fun new(x: i64, y: i64): Self = Self { x: x, y: y };

    fun origin(): Self = Self.new(0, 0);
}

fun main() {
    println(Point.new(3, 4));
    println(Point.origin());
}
```

Output:

```text
Point { x: 3, y: 4 }
Point { x: 0, y: 0 }
```

## Step 4: Passing a value to its own mut method
Kind: fix (start gives E0508 "cannot pass `p` to a `mut self` method called on `p`", help "copy it first: `let w = p;` and pass `w`")

`add` on line 4 adds another point to `self`, and line 12 tries to add `p` to itself.

`lughac` refuses it with E0508, "cannot pass `p` to a `mut self` method called on `p`".
A `mut self` method works on `p` in place, and during the call `other` would be read from that same `p`.
`add` could then change `other` while it's still reading it, so `lughac` doesn't allow it.
`let copy = p;` makes a separate copy, and passing that is fine:

```lugha {12,13}
struct Point { x: i64, y: i64 }

impl Point {
    fun add(mut self, other: Point) {
        self.x += other.x;
        self.y += other.y;
    }
}

fun main() {
    let mut p = Point { x: 3, y: 4 };
    let copy = p;
    p.add(copy);
    println(p);
}
```
