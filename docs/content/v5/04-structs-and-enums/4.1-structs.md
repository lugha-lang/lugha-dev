## Step 1: Struct declaration
Kind: read

A struct is a type you declare yourself, with a name for each of its fields.
Line 1 declares `Point`, a struct with two fields, each with its type.
`Point` is declared at the top level, outside `main`, and it's a type you can use like `i64`.
Line 4 builds one, naming each field, and `p.x` on line 5 reads the field `x`.
Press Run.

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 4 };
    console.println(p.x);
    console.println(p.y);
}
```

Output:

```text
3
4
```

## Step 2: Printing structs
Kind: fix (start gives E0422 "`Point` doesn't implement `Display`", help "write `impl Display for Point { fun show(self): string = … }`, or show its debug form with `.debug()`")

Line 5 prints `p` itself.
Press Run.

E0422 says `Point` doesn't implement `Display`, the same error an array gave in Arrays.
The help offers `impl Display`, which comes in chapter 8, or `.debug()`, which works now.
Add `.debug()` after `p` on line 5, or press Solve.
A struct's debug form is its name, then each field and its value in braces, in the order `Point` declares them.

Start:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 4 };
    console.println(p);
}
```

Solution:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 4 };
    console.println(p.debug());
}
```

Output (solution):

```text
Point { x: 3, y: 4 }
```

## Step 3: Struct literals
Kind: fix (start gives E0413 "missing field `y` in `Point`")

`Point { x: 3, y: 4 }` is a struct literal, and line 4 now writes one with only `x`.
Press Run.

There's no default: `lughac` gives E0413, "missing field `y` in `Point`".
A struct literal gives every field a value, in any order.
Add `, y: 0` after `x: 3` on line 4, or press Solve.

Start:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3 };
    console.println(p.debug());
}
```

Solution:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 0 };
    console.println(p.debug());
}
```

Output (solution):

```text
Point { x: 3, y: 0 }
```

## Step 4: Field assignment
Kind: fix (start gives E0501 "cannot assign to `p`: it is not mutable", help "make it mutable: `let mut p`")

Line 5 changes one field, `p.x = 5`, and `p` was declared with plain `let`.
Press Run.

E0501 names `p` itself: "cannot assign to `p`: it is not mutable".
A field has no `mut` of its own, so changing one changes the struct, and the variable that holds it needs `let mut`.
Add `mut` after `let` on line 4, or press Solve.

Start:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 4 };
    p.x = 5;
    console.println(p.debug());
}
```

Solution:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let mut p = Point { x: 3, y: 4 };
    p.x = 5;
    console.println(p.debug());
}
```

Output (solution):

```text
Point { x: 5, y: 4 }
```

## Step 5: Struct update syntax
Kind: read

Another way to get a changed point is to build a new one from the old.
Line 5 writes `x` and ends with `..p`, which takes every field not written, here `y`, from `p`.
Press Run.

Line 6 prints the new point, and line 7 prints `p` as it was: `..p` copies from `p` and leaves it alone.
`..p` has to come last, after the fields you write.

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let p = Point { x: 3, y: 4 };
    let shifted = Point { x: 10, ..p };
    console.println(shifted.debug());
    console.println(p.debug());
}
```

Output:

```text
Point { x: 10, y: 4 }
Point { x: 3, y: 4 }
```

## Step 6: Struct equality
Kind: fix (start gives E0422 "`Point` doesn't implement `Eq`", help "add `with Eq` after `Point`'s declaration, or implement it by hand with `impl Eq for Point`")

Line 6 compares two points with `==`.
Press Run.

E0422 says `Point` doesn't implement `Eq`, which `==` and `!=` need.
Writing `with Eq` after the declaration gives `Point` both, and `==` then compares the two field by field.
Add `with Eq` after the `}` on line 1, or press Solve.

Start:

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let a = Point { x: 3, y: 4 };
    let b = Point { x: 3, y: 4 };
    console.println(a == b);
}
```

Solution:

```lugha
struct Point { x: i64, y: i64 } with Eq

fun main(console: Console) {
    let a = Point { x: 3, y: 4 };
    let b = Point { x: 3, y: 4 };
    console.println(a == b);
}
```

Output (solution):

```text
true
```

## Step 7: Struct literals in conditions
Kind: fix (start gives E0205 "struct literal in a condition must be in parentheses", help "wrap it in parentheses: `(Point { … })`")

Line 5 checks with `==` whether `p` is the origin.
Press Run.

It doesn't compile: the `{` after `Point` could start the literal or the `if`'s block, so `lughac` gives E0205, "struct literal in a condition must be in parentheses".
Parentheses around the literal end the doubt.
Put the literal on line 5 in parentheses, or press Solve.

Start:

```lugha
struct Point { x: i64, y: i64 } with Eq

fun main(console: Console) {
    let p = Point { x: 0, y: 0 };
    if p == Point { x: 0, y: 0 } {
        console.println("at the origin");
    }
}
```

Solution:

```lugha
struct Point { x: i64, y: i64 } with Eq

fun main(console: Console) {
    let p = Point { x: 0, y: 0 };
    if p == (Point { x: 0, y: 0 }) {
        console.println("at the origin");
    }
}
```

Output (solution):

```text
at the origin
```
