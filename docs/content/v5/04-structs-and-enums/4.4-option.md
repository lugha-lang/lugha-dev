## Step 1: Option instead of null
Kind: read

A value that may be missing has the type `Option`: either `Some` with the value inside, or `None`.
There's no null in Lugha, so an `Option` is how a missing value is written.
`find` on line 1 gives back a name's position, and there is none when the name isn't in the array, so its return type is `Option<i64>`.
Line 4 returns `Some(i)` when the name is found, and line 7 gives `None` once the loop ends without it.
Unlike `Shape`'s variants, `Some` and `None` can be written without the enum's name in front.
Press Run.

An `Option` prints through `.debug()`, as `Shape` did.

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main(console: Console) {
    let names = ["Ann", "Ben", "Cy"];
    console.println(find(names, "Ben").debug());
    console.println(find(names, "Dee").debug());
}
```

Output:

```text
Some(1)
None
```

## Step 2: Matching on Option
Kind: fix (start gives E0417 "non-exhaustive match: `.None` not covered" on line 13, help "add the missing arms, or `_ => …`")

`Option` is an enum, so a `match` gets at the value inside, as it did for `Shape`.
Line 13 matches on what `find` gives back for each name, and `.Some(i)` on line 14 names the position `i`.
Press Run.

E0417 on line 13: "non-exhaustive match: `.None` not covered".
A `match` covers every variant, and nothing here says what happens when a name isn't found.
Add `.None => console.println("{wanted} isn't there"),` after line 14, or press Solve.
`None` is built without a dot, but every variant in a pattern has its dot, `Some` and `None` included.

Start:

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main(console: Console) {
    let names = ["Ann", "Ben", "Cy"];
    for wanted of ["Ben", "Dee"] {
        match find(names, wanted) {
            .Some(i) => console.println("{wanted} is at {i}"),
        }
    }
}
```

Solution:

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main(console: Console) {
    let names = ["Ann", "Ben", "Cy"];
    for wanted of ["Ben", "Dee"] {
        match find(names, wanted) {
            .Some(i) => console.println("{wanted} is at {i}"),
            .None => console.println("{wanted} isn't there"),
        }
    }
}
```

Output (solution):

```text
Ben is at 1
Dee isn't there
```

## Step 3: Typing None
Kind: fix (start gives E0412 "cannot infer the type of `None`", help "annotate it: `let x: Option<i64> = None;`")

`first_big` on line 2 starts as `None`, because no number over 6 has been found yet.
Line 5 sets it to `Some(n)` when the loop finds one.
Press Run.

`lughac` stops at line 2 with E0412, "cannot infer the type of `None`".
As with an empty array, the type has to be known where `None` is written, and `lughac` doesn't look ahead to line 5 for it.
Add `: Option<i64>` after `first_big` on line 2, or press Solve.

Start:

```lugha
fun main(console: Console) {
    let mut first_big = None;
    for n of [3, 8, 5, 12] {
        if n > 6 {
            first_big = Some(n);
            break;
        }
    }
    console.println(first_big.debug());
}
```

Solution:

```lugha
fun main(console: Console) {
    let mut first_big: Option<i64> = None;
    for n of [3, 8, 5, 12] {
        if n > 6 {
            first_big = Some(n);
            break;
        }
    }
    console.println(first_big.debug());
}
```

Output (solution):

```text
Some(8)
```

## Step 4: unwrap_or, is_some and is_none
Kind: read

`is_none()` on line 12 and `is_some()` on line 13 say which variant an `Option` is, as a `bool`, without a `match`.
`unwrap_or(-1)` gives the value inside a `Some`, or `-1` for a `None`, so line 15 prints `-1` for the missing name.
Press Run.

```lugha
fun find(names: string[], wanted: string): Option<i64> {
    for i in 0..names.len {
        if names[i] == wanted {
            return Some(i);
        }
    }
    None
}

fun main(console: Console) {
    let names = ["Ann", "Ben", "Cy"];
    console.println(find(names, "Dee").is_none());
    console.println(find(names, "Ben").is_some());
    console.println(find(names, "Ben").unwrap_or(-1));
    console.println(find(names, "Dee").unwrap_or(-1));
}
```

Output:

```text
true
true
1
-1
```

## Step 5: Parsing numbers
Kind: fix (start gives E0404 "cannot apply `+` to `Option<i64>` and `i64`")

`parse_i64` reads a string that is only a whole number, with an optional `-` in front.
Its result is an `Option<i64>`: `Some` with the number, or `None` for text such as `"4.5"` or `"nine"`.
Line 4 adds `1` to what it gave back.
Press Run.

That's E0404, "cannot apply `+` to `Option<i64>` and `i64`", because the number is still inside the `Option`.
`unwrap_or(0)` takes it out, with `0` standing in when the text isn't a number.
Add `.unwrap_or(0)` after `parse_i64(typed)` on line 3, or press Solve.

Start:

```lugha
fun main(console: Console) {
    let typed = "41";
    let n = parse_i64(typed);
    console.println(n + 1);
}
```

Solution:

```lugha
fun main(console: Console) {
    let typed = "41";
    let n = parse_i64(typed).unwrap_or(0);
    console.println(n + 1);
}
```

Output (solution):

```text
42
```

## Step 6: pop
Kind: read

`pop` removes the last element of an array and returns it as `Some`, or `None` when the array is empty.
Like `push`, `pop` changes the array, so `stack` on line 2 needs `let mut`.
It holds two numbers, and lines 3 to 5 pop three times.
Press Run.

The third `pop` prints `None`: popping an empty array isn't an error, and line 6 goes on to print the array, empty now.

```lugha
fun main(console: Console) {
    let mut stack = [1, 2];
    console.println(stack.pop().debug());
    console.println(stack.pop().debug());
    console.println(stack.pop().debug());
    console.println(stack.debug());
}
```

Output:

```text
Some(2)
Some(1)
None
[]
```

## Step 7: Checked arithmetic
Kind: fix (start prints `255`, then panics: stderr `panic: integer overflow at src/main.la:4:27`, exit 101)

This is the program from Integer overflow, where `level + 10` stopped the program because 260 doesn't fit in a `u8`.
`checked_add` does the same addition and gives an `Option`: `Some` with the sum, or `None` where `+` would panic.
Press Run to see the panic again.

With `checked_add`, an overflow gives `None` instead of stopping the program.
On lines 3 and 4, write `level.checked_add(5).debug()` and `level.checked_add(10).debug()` in place of the sums, or press Solve.

Start:

```lugha
fun main(console: Console) {
```
