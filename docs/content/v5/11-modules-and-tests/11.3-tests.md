## Step 2: assert_eq and assert_ne
Kind: fix (Test: `area_of_three` fails with "assert_eq failed: left 6.0, right 9.0" at line 6 of `test/shapes_test.la`)

`assert` only says that it failed, so line 6 of `test/shapes_test.la` uses `assert_eq(a, b)` instead, which fails unless `a` and `b` are equal.
`assert_ne` on line 13 fails if they are equal.
When they fail, `assert_eq` prints both values, the first as left, and `assert_ne` the value both have.
`area` on line 3 of `shapes.la` isn't the one from Test functions.
Press Test.

`area_of_three` fails with "assert_eq failed: left 6.0, right 9.0": `area` gave 6.0, and the test expects 9.0.
The failure names line 6 of the test file, where `assert_eq` was called.
Line 3 of `shapes.la` multiplies the side by `2.0` instead of by itself.
Change `2.0` to `s.side` on line 3 of `shapes.la`, or press Solve, and press Test again.

Start, `src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * 2.0;
```

`test/shapes_test.la` (start and solution):

```lugha
import geometry.shapes;

@test
fun area_of_three() {
    let s = shapes.Square { side: 3.0 };
    assert_eq(shapes.area(s), 9.0);
}

@test
fun bigger_side_bigger_area() {
    let a = shapes.Square { side: 3.0 };
    let b = shapes.Square { side: 4.0 };
    assert_ne(shapes.area(a), shapes.area(b));
}
```

Solution, `src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;
```

Tests (start):

```text

    panic: assert_eq failed: left 6.0, right 9.0 at shapes_test.la:6:5
test test.shapes_test.bigger_side_bigger_area ... ok

2 tests: 1 passed, 1 failed
```

Tests (solution): both `ok`, "2 tests: 2 passed, 0 failed".

## Step 3: Running tests
Kind: fix (Test: `largest_of_none` fails with "index out of bounds: the length is 0 but the index is 0" at line 6 of `src/shapes.la`)

`largest` in `shapes.la` should give the largest of an array of squares, or `None` for an empty one, and the test file checks both.
Press Test.

`largest_of_none` fails with a panic, "index out of bounds", but each test runs as its own process, so `largest_of_two` still runs and passes.
The last line, "2 tests: 1 passed, 1 failed", counts the whole run.
Run builds the program without its tests, so only Test runs them.
Line 6 of `shapes.la` reads `squares[0]` before checking that there is one.
After line 5 of `shapes.la`, add `if squares.len == 0 { return None; }`, on three lines, or press Solve, and press Test again.

Start, `src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;

fun largest(squares: Square[]): Option<Square> {
    let mut best = squares[0];
    for s of squares {
        if s.side > best.side {
            best = s;
        }
    }
    return Some(best);
}
```

Solution, `src/shapes.la`:

```lugha
struct Square { side: f64 }

fun area(s: Square): f64 = s.side * s.side;

fun largest(squares: Square[]): Option<Square> {
    if squares.len == 0 {
        return None;
    }
    let mut best = squares[0];
    for s of squares {
        if s.side > best.side {
            best = s;
        }
    }
    return Some(best);
}
```

`test/shapes_test.la` (start and solution):

```lugha
import geometry.shapes;

@test
fun largest_of_none() {
    let none: shapes.Square[] = [];
    assert(shapes.largest(none).is_none());
}

@test
fun largest_of_two() {
    let a = shapes.Square { side: 2.0 };
    let b = shapes.Square { side: 3.0 };
    assert_eq(shapes.largest([a, b]).unwrap().side, 3.0);
}
```

Tests (start):

```text
test test.shapes_test.largest_of_none ... FAILED
    panic: index out of bounds: the length is 0 but the index is 0 at src/shapes.la:6:27
test test.shapes_test.largest_of_two ... ok

2 tests: 1 passed, 1 failed
```

Tests (solution): both `ok`, "2 tests: 2 passed, 0 failed".

## Notes

- Sources (skill and v18 spec at m239): `@test`, `assert`, `assert_eq`, `assert_ne`, each test its own process [tasks/testing; modules-and-packages]; "`assert_eq` and `assert_ne` (v16) type their two operands the same way" as `==` does, so `o == None` and `None == o` both work (spec, "Operand types").
- Every project was run through Test in the drafting sandbox (lughac 0.18.0 at m239); Run prints `9.0` in all three. The Tests text is built from the API's JSON as the site's `testtext.ts` does. Also run: `@test fun area_of(n: i64)` is E0434 "a test takes only `Console`, `Dir`, `Clock`, `Env`, `Entropy` and `Net` (and, with `@test(integration)`, `Fs` and `Proc`), each at most once, and returns nothing" (step 1).
- Review, first draft (reviewer and three readers): step 2 surprised the JS reader (the prose pointed only at the assertions); the rest predicted. Taken: step 1's "so" (the test file imports `geometry.shapes` because it's outside `src`: spec L1112, a program may import its own package as `N`), "any other", and the test name's parts; step 2 points at `shapes.la` before Test; step 3's "after it" (tests run in parallel), "Solve does the same", the Run sentence moved, and its solution's result (run: 2 passed).
- **Objective 2 doesn't match m239.** `assert_eq(None, o)` with `o: Option<i64> = None` passes, and so does `assert_eq(o, None)`: either side may be the untyped one, as the spec's "Operand types" says. The E0412 the outline names doesn't happen, so step 2 doesn't claim it. What m173 shows here is the failure's place, line 6 of the test (where `assert_eq` was called). The objective now reads "the failure names the test's line" (owner, 2026-11-21).
- Changed by v18: `main` takes `console: Console`; step 1's "takes no parameters … E0434" became "takes no parameters here", since tests may take capabilities (11.4); step 2 names the test's line.
- From v4 (owner's rules, 2026-11-20): no fix blocks; "Solve does it for you" is "or press Solve".
