## Step 1: Integer division
Kind: read

In the last lesson `height * 300` had to fit a `u8`, because arithmetic works on two numbers of the same type and gives that type.
So dividing two whole numbers gives a whole number, and line 2 prints `3`.
Press Run.

Line 3 prints `-3`: Lugha drops the fraction toward zero rather than rounding down.
`%` on line 4 takes its sign from the left side, giving `-1`.
The half survives only when both sides are floats, as on line 5.

```lugha
fun main(console: Console) {
    console.println(7 / 2);
    console.println(-7 / 2);
    console.println(-7 % 2);
    console.println(7.0 / 2.0);
}
```

Output:

```text
3
-3
-1
3.5
```

## Step 2: Conversion with as
Kind: fix (start gives E0401 "float literal where i32 expected")

To get half of `total`, an `i32`, line 3 divides it by `2.0`.
Press Run.

`lughac` refuses it with E0401.
The `2.0` takes its type from `total` on the other side of the `/`, as the `300` did in the last lesson, and a float can't be an `i32`.
`as` converts a number to another type when nothing can be lost, and every `i32` has an exact `f64`.
Write `total as f64 / 2.0` on line 3 and run again, or press Solve: `as` is worked out before `/`, so `total` is converted first.

Start:

```lugha
fun main(console: Console) {
    let total: i32 = 7;
    let half = total / 2.0;
    console.println(half);
}
```

Solution:

```lugha
fun main(console: Console) {
    let total: i32 = 7;
    let half = total as f64 / 2.0;
    console.println(half);
}
```

Output (solution):

```text
3.5
```

## Step 3: Narrowing conversions
Kind: fix (start gives E0469 twice: "`as` can lose information: `i64` to `u8`" on line 3, and "… `i64` to `f64`" on line 4)

Lines 3 and 4 convert `total`, an `i64`, to a `u8` and an `f64` with `as`.
Press Run.

`lughac` gives E0469 for both.
`as` goes by the types, not the value: an `i64` can be too big for a `u8`, or too large for an `f64` to hold exactly.
Methods do these conversions instead, with the target type in `<…>`, each named for what it does when a number doesn't fit.
`truncate<u8>()` keeps the lowest 8 bits, so `300` becomes `44`, and `round<f64>()` takes the nearest `f64`.
Lines 5 and 6 already use two more: `saturate<u8>()` stops at the largest `u8`, and `try_into<u8>()` gives a value only when it fits, which `is_some()` checks.
Write `total.truncate<u8>()` on line 3 and `total.round<f64>() / 7.0` on line 4, or press Solve.

Start:

```lugha
fun main(console: Console) {
    let total = 300;
    console.println(total as u8);
    console.println(total as f64 / 7.0);
    console.println(total.saturate<u8>());
    console.println(total.try_into<u8>().is_some());
}
```

Solution:

```lugha
fun main(console: Console) {
    let total = 300;
    console.println(total.truncate<u8>());
    console.println(total.round<f64>() / 7.0);
    console.println(total.saturate<u8>());
    console.println(total.try_into<u8>().is_some());
}
```

Output (solution):

```text
44
42.857142857142854
255
false
```

## Step 4: Integer overflow
Kind: read

Arithmetic on whole numbers never wraps around the way `truncate` does: when a result won't fit, the program stops.
`level` is a `u8` holding 250, so line 3 prints `255`, its largest value, and line 4 adds 10.
Press Run.

After `255`, the program panics with `integer overflow`, names the line and column, and exits with code 101.
Dividing a whole number by zero stops a program the same way, while a float divided by zero doesn't stop it: `1.0 / 0.0` gives `inf`.

```lugha
fun main(console: Console) {
    let level: u8 = 250;
    console.println(level + 5);
    console.println(level + 10);
}
```

Output (stdout; stderr has `panic: integer overflow at src/main.la:4:27`, exit 101):

```text
255
```

## Step 5: Sizes in bytes
Kind: read

Whole numbers have methods for sizes in bytes: `kb()`, `mb()` and `gb()` multiply by powers of 1024.
Press Run.

Line 2 prints `8192`, eight times 1024, and line 3 prints 64 times 1024 times 1024.
The result keeps the type of the number it's called on, so line 5's is a `u32`, like `pages`.

```lugha
fun main(console: Console) {
    console.println(8.kb());
    console.println(64.mb());
    let pages: u32 = 3;
    console.println(pages.kb());
}
```

Output:

```text
8192
67108864
3072
```

## Step 6: Comparison and logical operators
Kind: fix (start gives E0203 "`<=` and `<` can't be chained", help "combine comparisons with `&&`: `(a <= b) && (b < c)`")

Comparisons give a `bool`, and line 4 checks in one go that `age` is at least 18 and under 65.
Press Run.

Comparisons don't chain, so `lughac` stops at E0203.
The two halves are joined with `&&`: write `18 <= age && age < 65` on line 4 and run it again, or press Solve.
Line 5 uses `!` for not and `||` for or, and `&&` and `||` stop as soon as the answer is known.
So when `zero` is 0, `zero != 0 && 10 / zero > 1` is `false` and the division by zero from step 4 never runs.

Start:

```lugha
fun main(console: Console) {
    let age = 30;
    let member = false;
    console.println(18 <= age < 65);
    console.println(!member || age > 60);
}
```

Solution:

```lugha
fun main(console: Console) {
    let age = 30;
    let member = false;
    console.println(18 <= age && age < 65);
    console.println(!member || age > 60);
}
```

Output (solution):

```text
true
true
```
