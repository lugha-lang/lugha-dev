# 5.2 mut parameters (v5, Lugha v18; new lesson)

## Objectives

1. **mut parameters**: `fun bump(mut c: Counter)` changes the caller's variable; checked in the sandbox at m238, `bump(mut c)` prints the change. [m166]
2. **mut at the call**: the call writes `mut` exactly where the parameter has it (E0443). [m166]
3. **Mutable places only**: an argument must be a `let mut` variable or a part of one (E0501). [m166]
4. **No aliasing**: the same variable twice in one call is E0508. [m166]

---

## Step 1: mut parameters
Kind: read

`bump` on line 3 has a `mut` parameter, `c`.
A parameter without `mut` is a copy of what the caller passed, but through a `mut` parameter the function changes the caller's own variable.
Line 4 adds `by` to `c.n`.
Lines 9 and 10 call `bump`, and each writes `mut c` for that parameter.
`main`'s `c` goes to `bump`'s `c` because it's the first argument, not because the names match.
Press Run.

Line 11 prints `5`: each call changed `c` in `main`, the first adding `2` and the second `3`.

```lugha
struct Counter { n: i64 }

fun bump(mut c: Counter, by: i64) {
    c.n += by;
}

fun main(console: Console) {
    let mut c = Counter { n: 0 };
    bump(mut c, 2);
    bump(mut c, 3);
    console.println(c.n);
}
```

Output:

```text
5
```

## Step 2: mut at the call
Kind: fix (start gives E0443 "this parameter is `mut`: the call changes the place you pass", help "write `mut x` for it, with `x` a `let mut` variable or a part of one")

Line 9 now calls `bump(c, 2)`, with no `mut` before `c`.
Press Run.

The program doesn't run.
A call changes what it passes to a `mut` parameter, so the call has to say so: the `mut` is written at the call as well as on the parameter.
E0443 says the parameter is `mut` and "the call changes the place you pass".
A place is somewhere a value is kept: a variable, or a field or element of one.
Its help says to write `mut x`, with `x` a `let mut` variable or a part of one.
It works the other way too: `mut` before an argument whose parameter has no `mut` is also E0443.
Write `mut c` on line 9 and run again, or press Solve.

Error note: `bump`'s parameter `c` is `mut`, so the call changes the variable it's given, and the call has to say so by writing `mut c` rather than `c`.

Start:

```lugha
struct Counter { n: i64 }

fun bump(mut c: Counter, by: i64) {
    c.n += by;
}

fun main(console: Console) {
    let mut c = Counter { n: 0 };
    bump(c, 2);
    console.println(c.n);
}
```

Solution:

```lugha
struct Counter { n: i64 }

fun bump(mut c: Counter, by: i64) {
    c.n += by;
}

fun main(console: Console) {
    let mut c = Counter { n: 0 };
    bump(mut c, 2);
    console.println(c.n);
}
```

Output (solution):

```text
2
```

## Step 3: Mutable places only
Kind: fix (start gives E0501 "cannot pass `c` as `mut`: it is not mutable", help "make it mutable: `let mut c`")

Line 9 passes `c` as `mut`, and line 8 declares `c` with a plain `let`.
Press Run.

The program doesn't run.
A `mut` argument is changed by the call, so it has to be a place that can change: a variable declared `let mut`, or a field or element of one.
E0501 says it cannot pass `c` as `mut` because `c` is not mutable, and its help suggests `let mut c`.
An element works the same way: `bump(mut counters[1], 5)` changes the second counter in a `let mut` array.
Add `mut` after `let` on line 8 and run again, or press Solve.

Error note: `bump` changes the variable passed to its `mut` parameter, so that variable has to be declared `let mut`, and `c` on line 8 is a plain `let`.

Start:

```lugha
struct Counter { n: i64 }

fun bump(mut c: Counter, by: i64) {
    c.n += by;
}

fun main(console: Console) {
    let c = Counter { n: 0 };
    bump(mut c, 2);
    console.println(c.n);
}
```

Solution:

```lugha
struct Counter { n: i64 }

fun bump(mut c: Counter, by: i64) {
    c.n += by;
}

fun main(console: Console) {
    let mut c = Counter { n: 0 };
    bump(mut c, 2);
    console.println(c.n);
}
```

Output (solution):

```text
2
```

## Step 4: No aliasing
Kind: fix (start gives E0508 "cannot pass `c` as `mut` and also as another argument", help "copy it first, so the call reads a value that doesn't change: `let w = c;` and pass `w`")

`add_to` on line 3 adds `other`'s count to `total`, its `mut` parameter.
Line 9 passes `c` as both arguments, to double its count.
Press Run.

The program doesn't run.
A `mut` parameter works on the caller's variable itself.
Without `mut`, a parameter acts as a copy because the function can't change it, but a struct isn't actually copied: the function reads it where it is.
So with `c` as both, `add_to` would change `c` through `total` and see that change through `other`.
E0508 says `c` can't be passed as `mut` and also as another argument, and its help says to copy it first, so the call reads a value that doesn't change.
Put `let w = c;` on a line before line 9 and pass `w` as the second argument, then run again, or press Solve.

Error note: `total` changes `c` itself, and `other` reads `c` where it is, so `add_to` would see its own change to `total` through `other`. Copy `c` first and pass the copy as `other`.

Start:

```lugha
struct Counter { n: i64 }

fun add_to(mut total: Counter, other: Counter) {
    total.n += other.n;
}

fun main(console: Console) {
    let mut c = Counter { n: 4 };
    add_to(mut c, c);
    console.println(c.n);
}
```

Solution:

```lugha
struct Counter { n: i64 }

fun add_to(mut total: Counter, other: Counter) {
    total.n += other.n;
}

fun main(console: Console) {
    let mut c = Counter { n: 4 };
    let w = c;
    add_to(mut c, w);
    console.println(c.n);
}
```

Output (solution):

```text
8
```

## Notes

- Sources (v18 spec at m238, section 4 "`mut` parameters", milestone 166): "changes its caller's place: the call writes `bump(mut c, 2)`, and `c` is changed when the call returns"; `mut` exactly where the parameter is (E0443); a mutable place: a `let mut` variable, a `mut` parameter, `mut self`, or a field or element of one (E0501, E0502); no other argument may be the same place (E0508). The skill's "still changes only the copy" [functions] contradicts this and the compiler; not used.
- Every program was run in the drafting sandbox (lughac 0.18.0 at m238). Also run: `mut c` passed to a parameter without `mut` is E0443 "this parameter isn't `out`, `ptr` or `mut`", help "… `mut` for a `mut` parameter: pass the value itself" (step 2's last sentence); `bump(mut counters[1], 5)` on a `let mut` array of two counters prints `[Counter { n: 0 }, Counter { n: 15 }]` (step 3's last sentence); `bump(mut Counter { n: 0 }, 2)` is E0502 "cannot pass this expression as `mut`" (not used).
- Review, first draft (reviewer and three readers): step 2 surprised the JS reader (`mut` at the call looked optional), step 4 the Python reader (predicted `8`); the rest were predicted. Taken: step 1's last sentence (it read as if `p.shift(10)` wrote `mut`); step 2's reason, now the message's own "place", defined once; step 3's "has to be a variable declared `let mut`" (the spec also allows a `mut` parameter and `mut self`). Kept: "pass `w` on line 9", worded as approved in 4.2 step 4.
- Not taught here (spec): returning or storing a `mut` parameter reads a copy; `spawn` with a `mut` argument (E0438), actor messages (E0439), a function with one as a value (E0406), closures (E0209). The last four belong with chapters 7 and 12 if wanted.
