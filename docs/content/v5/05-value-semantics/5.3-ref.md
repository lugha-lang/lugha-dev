## Step 1: Ref boxes
Kind: read

A `Ref` is a box: a place that holds one value, read with `get` and replaced with `set`.
`Ref.new(1)` on line 2 makes a box holding `1`, and `a` names it.
Line 3 copies `a` into `b`, line 4 calls `set(5)` on `b`, and line 5 prints `a.get()`.
Press Run.

It prints `5`.
Copying a `Ref` copies only a handle to the box, so `a` and `b` name the same box:

Diagram: v4's `diagram.svg`, kept (alt "a and b both point at one box, which holds 5").

Every other value you have met so far gives you a copy of your own when you copy it, as in Copies.

```lugha
fun main(console: Console) {
    let a = Ref.new(1);
    let b = a;
    b.set(5);
    console.println(a.get());
}
```

Output:

```text
5
```

## Step 2: set without mut
Kind: read

In the last step, `b.set(5)` worked on a plain `let b`, though `push` on an array needs `let mut`.
`set` changes the box, and `b` still names the same box.
`let mut` is needed only to point a name at another box.
`count` on line 2 is a plain `let` too, and line 3 calls `set(3)` on it.
Press Run.

```lugha
fun main(console: Console) {
    let count = Ref.new(0);
    count.set(3);
    console.println(count.get());
}
```

Output:

```text
3
```

## Step 3: get returns a copy
Kind: read

Line 4 puts a `Point` in a box, line 5 gets it out with `get`, and line 6 changes `p.x`.
Line 7 prints what's in the box.
Press Run.

It prints `Point { x: 1, y: 2 }`.
`get` gives a copy of what's in the box, so changing `p` never reaches the box.
To change the box, put a value back with `set`.

```lugha
struct Point { x: i64, y: i64 }

fun main(console: Console) {
    let shared = Ref.new(Point { x: 1, y: 2 });
    let mut p = shared.get();
    p.x = 9;
    console.println(shared.get().debug());
}
```

Output:

```text
Point { x: 1, y: 2 }
```

## Step 4: Updating a box
Kind: fix (start gives E0404 "cannot apply `+` to Ref<i64> and i64", help "compare boxes with `a.is(b)` (the same box) or `a.get() == b.get()` (the same contents)")

Line 5 tries to add `1` to `count` and put the result back.
Press Run.

E0404 calls `count` a `Ref<i64>`, a box holding an `i64`, and `+` needs the `i64` inside it.
The help under the error is about comparing boxes, which line 5 doesn't do.
`update` takes a function that gets an `i64` and returns one, calls it with what's in the box, and puts back what it returns.
`count.set(count.get() + 1)` does the same with two calls.
`add_one` on line 1 is such a function, and `update` takes it by name: `add_one(0)` would call it, but `add_one` alone hands over the function.
Write `count.update(add_one)` on line 5, or press Solve.

Start:

```lugha
fun add_one(n: i64): i64 = n + 1;

fun main(console: Console) {
    let count = Ref.new(0);
    count.set(count + 1);
    console.println(count.get());
}
```

Solution:

```lugha
fun add_one(n: i64): i64 = n + 1;

fun main(console: Console) {
    let count = Ref.new(0);
    count.update(add_one);
    console.println(count.get());
}
```

Output (solution):

```text
1
```

## Step 5: Identity with is
Kind: fix (start gives E0404 "cannot apply `==` to `Ref<i64>`" on lines 5 and 6, with the same help)

`b` on line 3 is a copy of `a`, so the two name one box, and `c` on line 4 is a second box that also holds `1`.
Lines 5 and 6 compare them with `==`.
Press Run.

That's E0404 again, "cannot apply `==` to `Ref<i64>`", with the help from the last step.
Boxes have no `==`.
`a.is(b)` says whether both name the same box, and `a.get() == b.get()` compares what's inside.
To see which names share a box, change `a == b` to `a.is(b)` on line 5 and `a == c` to `a.is(c)` on line 6, or press Solve.

Start:

```lugha
fun main(console: Console) {
    let a = Ref.new(1);
    let b = a;
    let c = Ref.new(1);
    console.println(a == b);
    console.println(a == c);
}
```

Solution:

```lugha
fun main(console: Console) {
    let a = Ref.new(1);
    let b = a;
    let c = Ref.new(1);
    console.println(a.is(b));
    console.println(a.is(c));
}
```

Output (solution):

```text
true
false
```

## Step 6: Linked structures
Kind: read

`Node` on line 1 links to the next node through `Option<Ref<Node>>`: `None` at the end, or a box holding the next node.
Line 5 links `first` to the box `second`, and line 6 calls `set` on `second`.
Line 7 takes the box out of `first.next`, and line 8 prints the value of the node in it.
Press Run.

It prints `20`, because `first` holds the same box as `second`.
A plain `Option<Node>` would also compile, but `first` would then hold its own copy of the next node, and no later change to `second` would reach it.

```lugha
struct Node { value: i64, next: Option<Ref<Node>> }

fun main(console: Console) {
    let second = Ref.new(Node { value: 2, next: None });
    let first = Node { value: 1, next: Some(second) };
    second.set(Node { value: 20, next: None });
    if let .Some(next) = first.next {
        console.println(next.get().value);
    }
}
```

Output:

```text
20
```
