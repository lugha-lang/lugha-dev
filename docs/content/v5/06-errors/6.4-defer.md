## Step 1: defer
Kind: read

`defer` sets a statement aside to run when the block it's in is left.
Line 3 defers a `console.println` that reads `n`, and line 4 changes `n` after it.
Press Run.

Line 5 prints first, `end of main: n is 2`.
The deferred line runs when `main` ends, after line 5, and reads `n` as it is then, so it prints `2` too.

```lugha
fun main(console: Console) {
    let mut n = 1;
    defer console.println("deferred: n is {n}");
    n = 2;
    console.println("end of main: n is {n}");
}
```

Output:

```text
end of main: n is 2
deferred: n is 2
```

## Step 2: defer and early returns
Kind: read

A defer runs on every way out of its block, a `return` or a `?` included.
`average` prints `starting` on line 9 and defers a line printing `finished` on line 10, before line 11 divides with `?`.
Lines 16 and 17 call it with a count of `2`, then `0`.
Press Run.

For the count of `2`, `average` prints `starting`, then `finished` as it ends, and line 16 prints `Ok(5)`.
For `0`, the `?` on line 11 returns the `Err` at once, but line 10's `defer` was already reached, so `finished` still prints before line 17 prints the `Err`.
So cleanup written as a `defer` near the top of a function also runs when a later `?` returns early.

```lugha
fun divide(a: i64, b: i64): Result<i64, string> {
    if b == 0 {
        return Err("division by zero");
    }
    Ok(a / b)
}

fun average(console: Console, total: i64, count: i64): Result<i64, string> {
    console.println("starting {total} / {count}");
    defer console.println("finished {total} / {count}");
    let avg = divide(total, count)?;
    Ok(avg)
}

fun main(console: Console) {
    console.println(average(console, 10, 2).debug());
    console.println(average(console, 10, 0).debug());
}
```

Output:

```text
starting 10 / 2
finished 10 / 2
Ok(5)
starting 10 / 0
finished 10 / 0
Err("division by zero")
```

## Step 3: Defer order
Kind: read

When a block has several defers, they run last first.
Lines 2 and 3 defer two lines in `main`.
Line 5's defer is inside the loop's body, so it belongs to the body, not to `main`, and runs at the end of each pass.
Press Run.

Each pass prints `pass {i}` from line 6, then `end of pass {i}` from its defer as the pass ends.
Then line 8 prints `end of main`, and as `main` ends its defers run last first: line 3's `second defer`, then line 2's `first defer`.

```lugha
fun main(console: Console) {
    defer console.println("first defer");
    defer console.println("second defer");
    for i in 1..3 {
        defer console.println("end of pass {i}");
        console.println("pass {i}");
    }
    console.println("end of main");
}
```

Output:

```text
pass 1
end of pass 1
pass 2
end of pass 2
end of main
second defer
first defer
```

## Step 4: defer and panics
Kind: read

A panic leaves blocks too, on its way to ending the program.
Line 2 defers a line printing `cleaning up`, and line 4 reads `ages[2]`, past the end of `ages`, which has two elements.
Press Run.

`cleaning up` prints first: as the panic leaves `main`, it runs `main`'s pending defer.
Then the panic gives the length and the index, and where it happened, and the program exits with code 101.

```lugha
fun main(console: Console) {
    defer console.println("cleaning up");
    let ages = [30, 41];
    console.println(ages[2]);
}
```

Output (stdout; stderr `panic: index out of bounds: the length is 2 but the index is 2 at src/main.la:4:25`, exit 101):

```text
cleaning up
```

## Step 5: Deferred values
Kind: fix (start gives E0456 "a deferred statement must have type (), found Result<(), string>", help "handle the error inside it, or discard it on purpose: `defer { let _ = fs.remove_file(tmp); }`")

`close` on line 1 is cleanup that can fail, so it gives back a `Result`, and line 7 defers it.
Press Run.

The program doesn't run.
A deferred statement's value would go nowhere, so it must have type `()`, and `close` gives a `Result<(), string>`.
E0456 says so, and its help says to handle the error inside it or discard it on purpose, with an example of a block holding a `let _ =`.
A block with only `close(console, "notes");` in it wouldn't do: that's a `Result` used as a statement, E0467.
Make line 7 `defer { let _ = close(console, "notes"); }`, which drops the `Result` on purpose, and run again, or press Solve.

Start:

```lugha
fun close(console: Console, name: string): Result<(), string> {
    console.println("closing {name}");
    Ok(())
}

fun main(console: Console) {
    defer close(console, "notes");
    console.println("working");
}
```

Solution:

```lugha
fun close(console: Console, name: string): Result<(), string> {
    console.println("closing {name}");
    Ok(())
}

fun main(console: Console) {
    defer { let _ = close(console, "notes"); }
    console.println("working");
}
```

Output (solution):

```text
working
closing notes
```

## Notes

- Sources (skill and v18 spec at m239): "`defer statement;` runs when its block is left, whichever way: the end, `return`, `?`, or a panic" [errors]; defers run last first, innermost block first (spec "defer", L988); a panic unwinds its task, running pending `defer`s (m194), except that a panic inside a `defer` ends the program at once (spec L1001); a deferred statement must be `()` (E0456), and a `Result` used as a statement is E0467 (m175).
- Every program was run in the drafting sandbox (lughac 0.18.0 at m239). Also run: `defer { close(console, "notes"); }` is E0467 "this `Result<(), string>` is discarded" (step 5's last sentence).
- Changed by v18: step 4 was "When defers don't run" (a panic skipped them, and so did `exit`); a panic now unwinds and runs them (m194), and the global `exit` is gone (E0471), so the step shows the defer running. Step 2 used `read_file` (files need an `Fs`, chapter 10) and now uses 6.2's `average`; step 5 used `write_file` and now defers a `close` that gives a `Result`, and its fix is `let _ =`, since a `;` no longer drops a `Result` (E0467). E0456's help names `fs.remove_file`, which this course meets in chapter 10.
- Review, first draft (reviewer and three readers): steps 2 to 4 were predicted by all three; step 1 surprised the Java reader (it expected `n` read when deferred), step 5 all three (two expected E0467). Taken: step 2's "as it does"; step 3's "loop's body"; step 4's "every block it leaves" (a panic in a `defer` stops the rest) and "on its way out of the program" (a panic in a task stops at its scope), now scoped to this program; step 5's instruction and its pointer to 6.1.
- For ../lugha: the spec contradicts itself on stack overflow. Its `defer` paragraph (L989) and Panics paragraph (L1001) say a stack overflow doesn't unwind or run `defer`s; L48 and "Recursion depth" (L1405, m205) say it does, and lughac does (its `control/unwinding/stack_overflow.la` prints `main unwound`). L989 and L1001 look stale.
