## Step 1: Interface values
Kind: fix (start gives E0403 "expected Circle, found Square")

An interface is also a type, and a `Shape` value can hold a value of any type that implements `Shape`.
`describe` in Interfaces took one as a parameter.
Line 17 puts a circle and a square in one array.
Press Run.

`lughac` stops at line 17 with E0403, "expected Circle, found Square": the array takes its type from its first element.
A value becomes a `Shape` only where a `Shape` is expected, so write the array's type: add `: Shape[]` after `shapes` on line 17, or press Solve.
The debug form of a `Shape` is the value inside it.

Start:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun main(console: Console) {
    let shapes = [Circle { r: 1.0 }, Square { side: 2.0 }];
    console.println(shapes.debug());
}
```

Solution:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun main(console: Console) {
    let shapes: Shape[] = [Circle { r: 1.0 }, Square { side: 2.0 }];
    console.println(shapes.debug());
}
```

Output (solution):

```text
[Circle { r: 1.0 }, Square { side: 2.0 }]
```

## Step 2: Method calls on interface values
Kind: read

`s.area()` on a `Shape` runs the `area` of the type inside it.
The loop on lines 19 to 21 adds up `s.area()` for a circle and a square, each with its own `area`.
A `Shape` has only its methods, though: `shapes[0].r` would be E0410, "no field `r` on `Shape`", and its help says to use a type pattern to reach the value inside.
Press Run.

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun main(console: Console) {
    let shapes: Shape[] = [Circle { r: 1.0 }, Square { side: 2.0 }];
    let mut total = 0.0;
    for s of shapes {
        total += s.area();
    }
    console.println(total);
}
```

Output:

```text
7.0
```

## Step 3: Type patterns
Kind: fix (start gives E0417 "non-exhaustive match: `_` not covered")

To reach the value inside a `Shape`, `match` on the type it holds.
`c: Circle` on line 18 matches when `s` holds a `Circle`, and names it `c`, a `Circle` with its fields.
`_: Square` on line 19 matches a square without naming it, since its arm doesn't need it.
Press Run.

`lughac` stops at line 17 with E0417, "non-exhaustive match: `_` not covered".
Any type that implements `Shape` could be inside, even one written later, so the `match` needs a `_` arm even with an arm for each type here.
Add `_ => "something else",` as a new line after line 19, or press Solve.

Start:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun kind(s: Shape): string {
    match s {
        c: Circle => "a circle of radius {c.r}",
        _: Square => "a square",
    }
}

fun main(console: Console) {
    console.println(kind(Circle { r: 2.0 }));
    console.println(kind(Square { side: 1.0 }));
}
```

Solution:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun kind(s: Shape): string {
    match s {
        c: Circle => "a circle of radius {c.r}",
        _: Square => "a square",
        _ => "something else",
    }
}

fun main(console: Console) {
    console.println(kind(Circle { r: 2.0 }));
    console.println(kind(Square { side: 1.0 }));
}
```

Output (solution):

```text
a circle of radius 2.0
a square
```

## Step 4: Interface conversion
Kind: fix (start gives E0403 "expected Shape[], found Circle[]")

`total` on line 16 takes a `Shape[]`, and line 20 passes `circles`, a `Circle[]`.
Press Run.

The call on line 20 is E0403, "expected Shape[], found Circle[]".
The conversion from the first step happens to a single value, never to an array or an `Option` around it.
An array's type is fixed where it's built, so make `circles` a `Shape[]` there: add `: Shape[]` after `circles` on line 19, or press Solve.
An interface value converts to another interface only if its own extends it: a `Pet` from Interfaces converts to a `Named`, but converting it to an interface `Loud` that `Dog` implements and `Pet` doesn't extend is E0422.

Start:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun total(shapes: Shape[]): f64 = shapes.fold(0.0, fun(sum, s) = sum + s.area());

fun main(console: Console) {
    let circles = [Circle { r: 1.0 }, Circle { r: 2.0 }];
    console.println(total(circles));
}
```

Solution:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun total(shapes: Shape[]): f64 = shapes.fold(0.0, fun(sum, s) = sum + s.area());

fun main(console: Console) {
    let circles: Shape[] = [Circle { r: 1.0 }, Circle { r: 2.0 }];
    console.println(total(circles));
}
```

Output (solution):

```text
15.0
```

## Step 5: Own methods and interface items
Kind: read

A type can have a method of its own and an interface's item with the same name.
`Circle` has its own `area` on line 8, in a plain `impl Circle`, and `Shape`'s `area` on line 12, in `impl Shape for Circle`.
Line 17 calls `c.area()`, and line 18 calls `Shape.area(c)`, naming the interface.
Press Run.

`c.area()` runs the type's own method, and `Shape.area(c)` the interface's item.
A `Shape` holding `c` runs the interface's item too: `s.area()` on it gives `3.0`.

```lugha
interface Shape {
    fun area(self): f64;
}

struct Circle { r: f64 }

impl Circle {
    fun area(self): f64 = self.r * self.r;
}

impl Shape for Circle {
    fun area(self): f64 = 3.0 * self.r * self.r;
}

fun main(console: Console) {
    let c = Circle { r: 1.0 };
    console.println(c.area());
    console.println(Shape.area(c));
}
```

Output:

```text
1.0
3.0
```
