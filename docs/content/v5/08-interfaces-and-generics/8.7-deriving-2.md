## Step 5: Writing an item by hand
Kind: fix (start gives E0463 "`Author` both derives and implements `Describe`" on line 21, help "keep one: remove `Describe` from `with`, or the `impl` block")

A type can write an interface by hand, with an `impl` block, instead of deriving it.
`Author` on line 21 asks for `Describe` with `with`, and `impl Describe for Author` on lines 23 to 25 writes its own.
Press Run.

The program doesn't run.
A type gets each interface one way, from the blocks or by hand, never both.
E0463 says so on line 21: "`Author` both derives and implements `Describe`".
Its help says to keep one.
Keep the `impl`: it then replaces the blocks for `Author`, and `Book` keeps them.
Remove `with Describe` from line 21 and run again, or press Solve.

Start:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive Describe for string {
    fun describe(self): string = "\"{self}\"";
}

fun part<F: Describe>(ctx: (), name: string, field: F): string = "{name} is {field.describe()}";

derive Describe for struct {
    fun describe(self): string = derive.fields(self, (), part).join(", ");
}

struct Book { title: string, pages: i64 } with Describe

struct Author { name: string, born: i64 } with Describe

impl Describe for Author {
    fun describe(self): string = "{self.name}, born {self.born}";
}

fun tell<T: Describe>(x: T): string = x.describe();

fun main(console: Console) {
    console.println(tell(Book { title: "Dune", pages: 412 }));
    console.println(tell(Author { name: "Frank Herbert", born: 1920 }));
}
```

Solution:


## Step 6: Overlapping blocks
Kind: fix (start gives E0452 "two `derive Describe` blocks cover `i64[]`" on line 13)

A block can take type parameters, as line 9 does: it covers `T[]` for every `T` that has `Describe`.
Line 13 adds a block for `i64[]`.
Line 20's `[1, 2, 3]` is an `i64[]`.
Line 21's `[[1], [2]]` is an `i64[][]`, an array of `i64[]`s, so line 9 covers it with `i64[]` as its `T`.
A block must also be in the module that declares its interface: `derive Display for i64` in this file would be E0452 too, as `impl Display for bool` is E0459.
Press Run.

The program doesn't run.
Each type gets its items from exactly one block, and lines 9 and 13 both cover `i64[]`.
E0452 says so on line 13: "two `derive Describe` blocks cover `i64[]`".
Its help says to remove or narrow one of them.
Remove lines 13 to 15 and run again, or press Solve.

Start:

```lugha
interface Describe {
    fun describe(self): string;
}

derive Describe for i64 {
    fun describe(self): string = "{self}";
}

derive<T: Describe> Describe for T[] {
    fun describe(self): string = "a list of {self.len}";
}

derive Describe for i64[] {
    fun describe(self): string = "some numbers";
}

fun tell<T: Describe>(x: T): string = x.describe();

fun main(console: Console) {
    console.println(tell([1, 2, 3]));
    console.println(tell([[1], [2]]));
}
```

Solution:


## Step 7: derive.all and derive.fold
Kind: read

`Gauge` on line 1 has two items, and the struct block on line 15 writes both.
Line 7 writes `i64` where the interface says `Self`, since the block is for `i64`; line 16, in the struct block, keeps `Self`.
`derive.all(self, other, near)` on line 16 calls `near` on each pair of matching fields and is `true` when every call is, stopping at the first `false`.
`near` gets the field's name and the two values; there is no `ctx`.
`derive.fold(self, 0, add_up)` on line 17 starts from `0` and passes the running result through `add_up` once per field, as `sum`.
`Reading` on line 20 asks with `with Gauge`.
Press Run.

Both lines show `45` for `a`, `20` plus `25`.
The first is close: each field is within 1 of the other reading's.
The second isn't, since `20` and `23` are 3 apart.

```lugha
interface Gauge {
    fun close_to(self, other: Self): bool;
    fun total(self): i64;
}

derive Gauge for i64 {
    fun close_to(self, other: i64): bool = self - other <= 1 && other - self <= 1;
    fun total(self): i64 = self;
}

fun near<F: Gauge>(name: string, x: F, y: F): bool = x.close_to(y);

fun add_up<F: Gauge>(sum: i64, name: string, part: F): i64 = sum + part.total();

derive Gauge for struct {
    fun close_to(self, other: Self): bool = derive.all(self, other, near);
    fun total(self): i64 = derive.fold(self, 0, add_up);
}

struct Reading { morning: i64, evening: i64 } with Gauge

fun compare<T: Gauge>(a: T, b: T): string = "{a.total()} and {b.total()}, close: {a.close_to(b)}";

fun main(console: Console) {
    let a = Reading { morning: 20, evening: 25 };
    console.println(compare(a, Reading { morning: 21, evening: 24 }));
    console.println(compare(a, Reading { morning: 23, evening: 25 }));
}
```

Output:

```text
45 and 45, close: true
45 and 48, close: false
```

## Step 8: derive.build
Kind: read

An interface item can take no `self`, as `parse` on line 2 does, and it's called on a type, as `T.parse(s)` on line 26.
`derive.build(s.split(","), field)` on line 21 builds a struct one field at a time, calling `field` on line 13 once per field with `F` set to that field's type: `string` for `title` and `i64` for `pages`.
`field` gets the split parts as `ctx`, then the field's name, its position from 0, and the number of fields.
Line 17 parses one part with `F`'s own `parse`, so each field is read at its own type.
The first `Err` stops it and is the result; otherwise it's `Ok` with the struct.
Press Run.

`"Dune,412"` parses into a `Book`.
`"Dune,many"` stops at `pages`, with the `i64` block's `Err`.
`"Dune"` splits into one part, so `field` gives back its own `Err`.

```lugha
interface Parse {
    fun parse(s: string): Result<Self, string>;
}

derive Parse for i64 {
    fun parse(s: string): Result<i64, string> = parse_i64(s).ok_or("`{s}` isn't a number");
}

derive Parse for string {
    fun parse(s: string): Result<string, string> = Ok(s);
}

fun field<F: Parse>(parts: string[], name: string, at: i64, count: i64): Result<F, string> {
    if parts.len != count {
        return Err("expected {count} parts, got {parts.len}");
    }
    return F.parse(parts[at]);
}

derive Parse for struct {
    fun parse(s: string): Result<Self, string> = derive.build(s.split(","), field);
}

struct Book { title: string, pages: i64 } with Parse

fun read<T: Parse>(s: string): Result<T, string> = T.parse(s);

fun main(console: Console) {
    for line of ["Dune,412", "Dune,many", "Dune"] {
        let book: Result<Book, string> = read(line);
        console.println(book.debug());
    }
}
```

Output:

```text
Ok(Book { title: "Dune", pages: 412 })
Err("`many` isn't a number")
Err("expected 2 parts, got 1")
```

- Every program was run in the drafting sandbox (lughac 0.18.0 at m239). Also run: `impl Describe for Book = derive;` in place of `with` prints the same (step 1's last sentence); `Book { … }.describe()` with `with Describe` is E0415 "no method `describe` on `Book`" (step 3's last sentence); `derive Display for i64` is E0452 "a `derive` block for `Display` must be in the module that declares `Display`" (step 6).
- For ../lugha, seen while drafting: (1) the spec says a block's items "never become methods of `X` (`5.show()` stays E0415)", but with step 2's blocks `5.describe()` prints `the number 5` at m239 (a struct's `.describe()` is E0415 as specified); step 2 therefore shows `Describe.describe(7)` and doesn't claim `5.describe()` fails (v4's step 1 was a fix of exactly that E0415). (2) E0452's help for a block outside the interface's module still says "a type's own methods can replace an item instead", which v18 no longer allows; step 6 doesn't quote it.
- Also run (review): `other: Self` in step 7's `i64` block is E0305 "cannot find type `Self`", with E0422 "`close_to` should be `fun close_to(self, i64): bool`" (why line 7 writes `i64`).
- (3) The spec (L767) says "`Eq` is still met without asking (v18, until `Key` arrives)", but at m239 a struct needs `with Eq` for `==` (4.1, 8.5), as step 1's "as it does for `Eq`" says.
